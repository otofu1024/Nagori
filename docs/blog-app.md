# Nagoriのブログのモード

- 作成日 2026-10-12
- 状態 段階1〜3とグラフビューを実装済み。テーマの選択、段階4・5は計画。

## 目的

Nagoriのブログのモードで、ブログ(yuzu notes)を書いて、見た目を整えて、GitHubへ反映するまでを扱います。テーマは外のエディタやAIでも書き換えます。ブログ以外のフォルダでは、汎用のMarkdownエディタとして使います。

今のブログ作りで面倒なのは、Front Matterの管理、公開までの手順、本番と同じ見た目での確認の3つです。このアプリはこの3つと、AIによる推敲と見た目の変更を扱います。

## 名前とモード

汎用のMarkdownエディタとブログ用のアプリを、公開リポジトリ`otofu1024/Nagori`の1つのアプリ「Nagori」にまとめます。識別子は`app.nagori.editor`、バージョンは0.1.1のままです。

開いたフォルダに`src/content/blog`、`src/theme/theme.css`、`src/config.ts`があれば、ブログのモードで開きます。シンボリックリンクを含む構成は対象外です。条件を満たさないフォルダは、これまでの汎用のモードで開きます。設定画面の「ブログの機能」は初期値がオンで、オフにするとブログのフォルダも汎用のモードで開きます。切り替えは開いているワークスペースにも反映します。

ブログのモードでは、ファイル一覧、ファイル名の検索、本文検索、グラフの対象を`src/content/blog`の下に限ります。記事のファイルを直接開いた時は、親を辿ってブログのルートを開きます。設定がオフの時は、従来どおりファイルの親フォルダを開きます。左右の欄と上のバーの見た目は、NagoriEditorのままです。ロゴは改名前のNagoriのワードマークに戻します。

## ブログの設定

設定画面の「ブログ」の欄には、先頭に「ブログの機能」、その下に次の4つの切り替えを置きます。初期値はすべてオンです。古い設定ファイルに項目がない時もオンで読みます。

| 項目 | オフの時の表示 |
|---|---|
| 記事の見出し | Front Matterを汎用のプロパティ一覧で表示 |
| リンクカード | URLだけの段落も普通のリンクで表示。新しいURLの情報は取得しない |
| キャラクターの吹き出し | `> [!キー]`を普通の引用で表示 |
| 本文のテーマ | `theme.css`と`template.css`を適用せず、Nagoriの見た目で表示 |

「ブログの機能」がオフの時は、4つの切り替えを押せません。個別の値は残り、ブログの機能をオンに戻すと同じ値を使います。切り替えは開いている記事へすぐ反映し、本文、カーソルの位置、Undoの履歴を保ちます。

同じ欄に「改行したら全角スペースで字下げする」を置きます。初期値と古い設定ファイルでの値はオンです。「ブログの機能」がオフの時は押せず、値は残ります。ブログのモードで段落の中でEnterを押すと、新しい行の先頭に全角スペースを1つ入れます。空の行や空白だけの行では入れません。行の途中で分けた時も字下げし、右側がすでに全角スペースで始まる時は重ねません。日本語変換中のEnterでは変更しません。改行と字下げは1回のUndoで戻せます。

段落の改行では、どのモードでも前の行の空白を半角スペースに置き換えて引き継ぎません。リスト、引用、コードブロック、表、Front Matter、見出しの行の改行は従来の処理を使います。

「本文のテーマ」をオフにすると、記事の見出し内やカード、吹き出しへのテンプレートのクラスの指定も外します。記事の見出しや部品の構造はそれぞれの設定に従い、色や文字はNagoriの見た目になります。

## 対象のブログ

nagori_templateの形のAstroのブログを、リポジトリのフォルダごと開きます。yuzu notesもテンプレートと同じ形へ移しています。アプリが読み書きするのは次の場所です。

| 場所 | 中身 |
|---|---|
| `src/content/blog/<日付>-<6文字>/index.md` | 記事。画像は記事フォルダの`assets/`に置く |
| `src/theme/theme.css` | 見た目 |
| `docs/theme-contract.md` | `theme.css`で使ってよい変数とクラスの一覧 |
| `src/config.ts` | ブログの名前、カテゴリー、キャラクター |
| `src/data/link-cards.json` | リンクカードのキャッシュ |

## 機能

### 1. 記事の設定と一覧

`src/content/blog`の下のMarkdownでは、先頭のFront Matterを記事の見出しとして表示します。Live Previewではその場で編集でき、Previewでは読み取り専用になります。YAMLとして読めない時は、そのまま表示して本文で直せるようにします。

見出しに出ない項目は、見出しの下の「プロパティ」を開くと編集できます。型のアイコン、項目名、値を1行ずつ並べ、順番はYAMLに書かれた順です。入れ子やアンカーなど、その場で安全に編集できない値は読み取り専用になります。一覧の末尾で入力してEnterを押すか、欄から離れると要素を追加します。

「+ プロパティを追加」から、まだ書かれていないテンプレートの項目を選んで追加できます。一覧内の「プロパティ」を押すとYAMLのソースが開き、カーソルを本文へ移すと見出し表示に戻ります。編集した項目だけを書き戻し、コメントと並び順は残します。変更は本文と同じ履歴と自動保存を使い、Cmd+Zで戻せます。日本語の変換中は書き戻しません。本文での編集と外部のファイル変更も表示に反映します。

左の欄、右の目次、上のバー、ファイルの作成や名前変更は、既存のエディタの機能を使います。汎用のモードでは値からプロパティの型を決め、項目名を入力して追加できます。ブログのモードのプロパティ表示は記事だけを対象にします。

### 2. 本文の見た目

段階3のプレビューは、別の画面を作らず、本文の欄をブログの記事ページの見た目に近づける形にしました。`astro dev`は動かしません。

ブログのモードでは、開いたフォルダの`src/styles/template.css`と`src/theme/theme.css`を読み、`.prose`の指定をNagoriの本文の部品へ読み替えて当てます。リンクカードとキャラクターの吹き出しは、ブログと同じ構造とクラス名で描き、指定を部品の入れ物の中だけに当てます。ファイルがない時や読めない時は、今までの見た目を使います。

記事の見出しは、カテゴリ、タイトル、説明文、公開日と更新日、読了時間、タグを、ブログの記事ページと同じ順番とクラス名で表示します。タイトルは`coverTitleLines`があればその行分けを使い、編集する時は`title`を表示します。カテゴリを押すと、開いたブログの`src/config.ts`の`CATEGORIES`から表示名を選び、キーを保存します。設定を読めない時は、今の値だけを候補にします。

タイトルと説明文はその場で入力でき、Enterで確定します。公開日と更新日は押すと日付を選べます。更新日がない記事では表示せず、下の一覧から追加します。タグは1つずつ削除でき、末尾で追加できます。読了時間は、空白を除いた本文の文字数を500で割って切り上げ、最低1分として本文の変更に合わせて更新します。必須のタイトル、説明文、公開日、カテゴリが空や不正な時は、その項目に印を付けます。

見出しの下には、`draft`、`cover`、`coverAlt`、`coverTitleLines`など、見出しに出ない項目をたたんだ一覧で置きます。開くと、既存のプロパティ欄と同じ見た目と操作で編集できます。開閉の状態は記事を移っても保ちます。

どこまでtheme.cssに従うかは、次のように決めています。色や飾りはブログに合わせ、本文の大きさや間隔はNagoriのままにします。

| 従う先 | 項目 |
|---|---|
| theme.css | 文字と背景と差し色とリンクの色、フォントの種類、リンクの飾り、引用・コード・表の飾り(背景、枠線、角丸、内側の余白)、コードの色分け、見出しの太さと下線と大きさ、記事の見出しの中の間隔と大きさ、リンクカードとキャラクターの吹き出しの中の見た目と間隔 |
| Nagori | 本文の文字の大きさ(拡大縮小)、行間、段落や見出しの上下の間隔、本文の幅(設定の幅) |

見出しの大きさは、本文の文字に対する比をブログに合わせ、拡大縮小に比例させます。行や部品の上下にmarginを付けると、本文の部品が行の高さを測り違えて矢印キーの移動先が飛ぶので、上下の間隔はNagoriの指定だけで作ります。

リンクカードと吹き出しも、入れ物でmarginを閉じ込めます。URLの段落や引用にカーソルが入ると、記法に戻して編集できます。カードの情報と画像は開いたブログのキャッシュを使い、未取得のURLはRust側で取得して同じ保存先へ追加します。取得中やネットにつながらない時は普通のリンクを表示します。

記事の見出しの中の指定は、見出しの入れ物の中だけに適用します。入れ物でmarginを閉じ込め、本文の行の高さと矢印キーの移動先に影響しないようにします。見出しの文字の大きさのremも本文の拡大縮小に比例させます。

テーマは本文の欄だけに適用します。Nagoriがダークモードでも、本文はブログの色で表示し、左右の欄と上のバー、設定画面、ダイアログはNagoriの配色を保ちます。外でどちらかのCSSを保存すると、再起動せずに本文へ反映します。設定の「ブログの機能」をオフにした時と、ブログ以外のフォルダでは、今までの見た目を使います。

次に、Nagoriにテーマをいくつか持たせます。テーマを選ぶと、ブログの`theme.css`を置き換えられるようにします。

### 3. GitHubへの反映の計画

公開ボタンを押すと、変更されたファイルの一覧とコミットメッセージの案を見せます。確かめて進めると、コミットしてGitHubへpushします。その先の公開は、今までどおりCloudflareがmainへのpushを受けて行います。アプリはビルドもデプロイもしません。

Gitの操作には、Macに入っているGitとGitHubの認証をそのまま使います。

### 4. AIの計画

右の欄にはブログの記事の添削の欄を置き、目次と切り替えて使います。記事のチャット、説明文とタグの案、推敲を扱い、テーマの変更はこの欄では扱いません。

#### 接続先

サブスクの公式のコマンドを、アプリが裏で1回ずつ動かします。アプリはサブスクのログインを真似せず、パスワードやAPIキーも持ちません。最初の接続先は、Antigravity CLI(`agy`)だけです。

| 使う機能 | 指定 |
|---|---|
| 1回だけ動かして答えを受け取る | `agy -p` |
| 答えの形を決める | `--output-format json`と`--json-schema` |
| 答えを途中から表示する | `--output-format stream-json` |
| 会話を続ける | `--conversation <ID>` |

`--dangerously-skip-permissions`は付けません。付けなければ、ファイルの書き換えやコマンドの実行は断られます。AIへ渡すのは、開いている記事の本文とFront Matterです。

接続先は差し替えられる作りにして、後でClaude Code(`claude -p`)やCodex(`codex exec`)を足せるようにします。

#### チャット

開いている記事について、AIと会話できます。「こういう内容の下書きを作って」と頼めば、下書きを返します。AIが本文の変更を提案した時は、差分で見せ、採用するかを選びます。

#### 説明文とタグの案

ボタンを押すと、本文から`description`と`tags`の候補を出します。タグは、ほかの記事ですでに使っているタグを優先します。候補は記事の設定欄に並び、使うものを選びます。

#### 推敲

ボタンを押すと、直した方がいい箇所を一覧で返します。指摘ごとに直した案が付き、1件ずつ採用するかを選びます。本文を勝手に書き換えることはしません。公開ボタンを押した時にも、同じ確認を行えるようにします。

推敲の基準は、Nagori用に新しく作ります。見るのは次の4つです。

| 観点 | 例 |
|---|---|
| 誤字脱字と表記の揺れ | 変換の誤り、同じ記事の中で「ユーザー」と「ユーザ」が混じる |
| 読みやすさ | 長すぎる文、主語と述語のねじれ、意味が通りにくい文 |
| 事実の確認 | 日付、数字、固有名詞、技術的な説明の誤りらしきもの |
| 公開前の確認 | 書きかけの段落、TODO、住所や電話番号などの個人情報らしきもの |

事実の確認は、AIがWebで調べられないと、古い知識で誤りと判断するおそれがあります。`agy`が許可なしでWeb検索を使えるかを確かめ、使えない場合は指摘に「AIの知識による」と添えて断定しない形にします。

#### キャラクターの管理

設定の「ブログ」から「キャラクターの管理」を開けます。ブログのモードの時だけ使え、設定ダイアログ内の別ページに一覧と編集欄を置きました。キー、名前、標準の表情の画像を一覧に出し、キャラクターと表情の追加、削除、名前の変更、表示名、別名、標準の表情を編集できます。

画像は選択かドロップで指定します。保存時に`public/images/<キーの小文字>/<表情名>.<元の拡張子>`へコピーし、同じ名前の画像があれば上書きを確認します。キーの文字と予約語、正規化した表情名と別名の重複、標準の表情を確かめ、合わない項目の横に理由を出します。

標準の表情はブログ側の照合に合わせて正規化して保存します。

`src/config.ts`は実行せずに構文木で読み、`CHARACTERS`の値の部分だけを書き換えます。ほかの設定、コメント、並び順は保ちます。空の`CHARACTERS`も保存でき、設定がない時や関数呼び出しなどの読めない形では保存しません。一時ファイル経由で置き換え、外で変更されていたら競合を知らせます。保存した設定は本文の吹き出しへすぐ反映します。

削除の前に`src/content/blog`の記事内で使われている数を数え、使われていれば件数を出して確認します。記事は書き換えません。設定を保存した後、ほかの表情やキャラクターが使っていない`public`の下の画像をNagoriのゴミ箱へ移します。設定の保存に失敗した時は、コピーした画像を元に戻します。

読み取り、検証、書き出し、使用数、画像の保存先とコピーの準備は`blogCharacterManager.ts`にまとめました。既存の構文木の解析器を使い、将来のMCPからも同じ処理を呼べるよう、画面から独立したTypeScriptのモジュールにしました。入出力は差し替えられ、アプリではRustの既存の保存とゴミ箱の処理を使います。

#### MCPによるテーマとキャラクターの変更

段階5のテーマの変更はMCPへ移します。外のCodex、Claude Code、AntigravityからMCPを使って`theme.css`を書き換えます。キャラクターの追加、削除、編集もMCPで扱えるようにします。MCPの操作は、設定のキャラクターの管理と同じ検証を通し、予約語やキーの文字を確かめます。書き換える前の内容を履歴に残します。右の添削の欄ではテーマを扱いません。

MCPでは、使ってよい変数とクラスの一覧、結果の画面の確認、書き換え前の`theme.css`の履歴を扱います。外で保存したテーマは、本文の欄へ反映します。

### 新しい記事

ブログのモードでは、左の欄の上にある「＋」と「新しいフォルダ」の横に「新しい記事」が表示されます。押すと、タイトル、説明、カテゴリ、タグの入力画面を開きます。必須はタイトルとカテゴリです。説明とタグは空でも作成できます。カテゴリは`src/config.ts`の`CATEGORIES`から選び、タグはほかの記事の候補から選ぶか、新しく入力して追加できます。追加したタグは個別に削除できます。

「作成」を押すと、日本時間の今日の日付とランダムな16進6文字を使った`src/content/blog/<YYYYMMDD>-<6文字>/index.md`を作り、その記事を開きます。左の一覧にも新しい記事が表示されます。Front Matterと本文はテンプレートの`npm run new-post`と同じ形です。説明が空なら`description: ""`、タグが空なら`tags: []`を書きます。同じ名前のフォルダがある場合は別の名前を作り直します。日本語の変換中のEnterでは作成しません。

入力の検証、日付、Markdownの組み立て、作成の呼び出しは`blogNewPost.ts`にまとめました。入出力を差し替えられるため、MCPからも同じ処理を呼べます。Rustの`blog_posts.rs`でフォルダとファイルを作り、既存のパス検証でシンボリックリンクを拒否します。

### 5. グラフビュー

左の欄の「ゴミ箱」の下にある「グラフビュー」を押すと、本文の場所に記事とタグのグラフを表示します。もう一度押すか、記事の点やファイル一覧から記事を開くと、エディタに戻ります。編集中の本文、Undo履歴、自動保存は保たれます。

`src/content/blog`のMarkdownを記事の点にし、Front Matterのtitleを名前に使います。titleがなければファイル名を表示します。tagsは別の色の点になり、記事と線でつながります。解決できる相対リンクと`/posts/<slug>`のブログ内リンクも線で結びます。Front Matterのslugがあれば使い、なければ記事のパスから拡張子と末尾のindexを外して解決します。同じslugの記事が複数あるリンクは線を作りません。`[[ファイル名]]`のリンクも解決します。

点は力学のシミュレーションで広がり、ドラッグした後もなめらかに落ち着きます。背景のドラッグで全体を移動し、ホイールやピンチで拡大縮小できます。カーソルを合わせるとつながりを強調し、名前は拡大した時に表示します。ファイルの変更は点の位置を保って反映し、動きが落ち着くとシミュレーションと描画を止めます。矢印キーで点を選び、Enterで記事を開けます。プラスとマイナスのキーでも拡大縮小できます。

## 作る順番

| 段階 | 内容 |
|---|---|
| 1 | 1つのNagoriでフォルダを判定し、ブログのリポジトリを開いて記事を書ける |
| 2 | 本文内のFront Matterをプロパティとして表示 |
| 3 | 本文の欄へブログの見た目を適用。次にテーマの選択 |
| 4 | GitHubへの反映 |
| 5 | 右の欄で記事の添削。テーマの変更は外のAIからMCPで扱う |

新しい記事は左の欄の「新しい記事」か、テンプレートの`npm run new-post`で作成できます。段階4ではターミナルでのpushを置き換えます。テーマの選択を次に作り、テーマを変更するMCPと記事の添削は段階5で扱います。

## 決めていないこと

| 項目 | 内容 |
|---|---|
| `agy`の作業フォルダ | 作業フォルダを指定する方法が公式の資料にない。空の作業用フォルダで起動する案 |
| `agy`のWeb検索 | 許可なしで使えるか、検索だけ許可できるか |
| 推敲の基準の中身 | 4つの観点ごとの具体的な決まり |
| 署名 | 自分用なのでad-hoc署名で足りる見込み |
