# Nagoriのブログのモード

- 作成日 2026-10-12
- 状態 段階1・2とグラフビューを実装済み。段階3以降は計画。

## 目的

Nagoriのブログのモードで、ブログ(yuzu notes)を書いて、見た目を整えて、GitHubへ反映するまでを1つのMacアプリで済ませます。ブログ以外のフォルダでは、汎用のMarkdownエディタとして使います。

今のブログ作りで面倒なのは、Front Matterの管理、公開までの手順、本番と同じ見た目での確認の3つです。このアプリはこの3つと、AIによる推敲と見た目の変更を扱います。

## 名前とモード

汎用のMarkdownエディタとブログ用のアプリを、公開リポジトリ`otofu1024/NagoriEditor`の1つのアプリ「Nagori」にまとめます。識別子は`app.nagori.editor`、バージョンは0.1.1のままです。

開いたフォルダに`src/content/blog`、`src/theme/theme.css`、`src/config.ts`があれば、ブログのモードで開きます。シンボリックリンクを含む構成は対象外です。条件を満たさないフォルダは、これまでの汎用のモードで開きます。設定画面の「ブログの機能」は初期値がオンで、オフにするとブログのフォルダも汎用のモードで開きます。切り替えは開いているワークスペースにも反映します。

ブログのモードでは、ファイル一覧、ファイル名の検索、本文検索、グラフの対象を`src/content/blog`の下に限ります。記事のファイルを直接開いた時は、親を辿ってブログのルートを開きます。設定がオフの時は、従来どおりファイルの親フォルダを開きます。左右の欄と上のバーの見た目は、NagoriEditorのままです。ロゴは改名前のNagoriのワードマークに戻します。

## 対象のブログ

nagori_templateの形のAstroのブログを、リポジトリのフォルダごと開きます。yuzu notesもテンプレートと同じ形へ移しています。アプリが読み書きするのは次の場所です。

| 場所 | 中身 |
|---|---|
| `src/content/blog/<日付>-<6文字>/index.md` | 記事。画像は記事フォルダの`assets/`に置く |
| `src/theme/theme.css` | 見た目 |
| `docs/theme-contract.md` | `theme.css`で使ってよい変数とクラスの一覧 |
| `src/config.ts` | ブログの名前、カテゴリー、キャラクター |
| `src/data/link-cards.json` | リンクカードのキャッシュ |

## 機能

### 1. 記事の設定と一覧

`src/content/blog`の下のMarkdownでは、本文の先頭のFront Matterを、Obsidianのプロパティと同じ形で表示します。Live Previewでは本文内のブロックとして編集でき、Previewでは同じ見た目で読み取り専用になります。「プロパティ」を押すとYAMLのソースが開き、カーソルを本文へ移すとプロパティ表示に戻ります。YAMLとして読めない時は、そのまま表示して本文で直せるようにします。

小さな見出し「プロパティ」の下に、型のアイコン、項目名、値を1行ずつ並べます。順番はYAMLに書かれた順です。枠や区切り線は付けず、本文と同じ背景、字体、色を使います。直後の空行は表示上だけ詰めます。

文字は1行の入力欄、公開日と更新日は日付の入力欄、一覧は削除できる丸いチップ、真偽値はチェックボックスで編集します。入れ子、アンカー、複数行の文字など、その場で安全に編集できない値は読み取り専用で表示します。一覧の末尾で入力してEnterを押すか、欄から離れると要素を追加します。日本語の変換中は書き戻しません。

最後の「+ プロパティを追加」から、まだ書かれていない`title`、`description`、`publishedAt`、`updatedAt`、`category`、`tags`、`draft`、`cover`、`coverAlt`、`coverTitleLines`を選んで追加できます。編集した項目だけを書き戻し、コメントと並び順は残します。変更は本文と同じ履歴と自動保存を使い、Cmd+Zで戻せます。本文での編集と外部のファイル変更も表示に反映します。

左の欄、右の目次、上のバー、ファイルの作成や名前変更は、既存のエディタの機能を使います。汎用のモードでは値からプロパティの型を決め、項目名を入力して追加できます。ブログのモードのプロパティ表示は記事だけを対象にします。

### 2. 本番と同じ見た目のプレビューの計画

記事の横か切り替えで、ブログの記事ページと同じ見た目のプレビューを出します。`astro dev`は動かしません。

nagori_templateは、見た目をすべて`theme.css`に集め、使えるクラスと変数を`theme-contract.md`に決めています。アプリは、テンプレートの記事ページ(`src/pages/posts/[...slug].astro`)と同じ構造のHTMLを作り、ブログの`theme.css`を読み込んで表示します。

MarkdownからHTMLを作る処理には、テンプレートと同じunifiedの処理と、ブログの`src/lib`にあるremarkとrehypeのプラグインを使う案です。吹き出しや日本語の強調を、ブログと同じ処理で作れます。リンクカードは、キャッシュにあるものだけをカードにします。

テンプレートの記事ページの構造が変わると、プレビューとずれます。テンプレートの記事ページとアプリのHTMLを比べる確認を、アプリのテストに入れます。

### 3. GitHubへの反映の計画

公開ボタンを押すと、変更されたファイルの一覧とコミットメッセージの案を見せます。確かめて進めると、コミットしてGitHubへpushします。その先の公開は、今までどおりCloudflareがmainへのpushを受けて行います。アプリはビルドもデプロイもしません。

Gitの操作には、Macに入っているGitとGitHubの認証をそのまま使います。

### 4. AIの計画

AIとのやり取りはアプリの中で完結させます。画面には、チャット欄と2つのボタンを置きます。

#### 接続先

サブスクの公式のコマンドを、アプリが裏で1回ずつ動かします。アプリはサブスクのログインを真似せず、パスワードやAPIキーも持ちません。最初の接続先は、Antigravity CLI(`agy`)だけです。

| 使う機能 | 指定 |
|---|---|
| 1回だけ動かして答えを受け取る | `agy -p` |
| 答えの形を決める | `--output-format json`と`--json-schema` |
| 答えを途中から表示する | `--output-format stream-json` |
| 会話を続ける | `--conversation <ID>` |

`--dangerously-skip-permissions`は付けません。付けなければ、ファイルの書き換えやコマンドの実行は断られます。AIへ渡すのは、開いている記事の本文、Front Matter、必要な時の`theme.css`と`theme-contract.md`です。

接続先は差し替えられる作りにして、後でClaude Code(`claude -p`)やCodex(`codex exec`)を足せるようにします。

#### チャット

開いている記事について、AIと会話できます。「こういう内容の下書きを作って」と頼めば、下書きを返します。AIが本文や`theme.css`の変更を提案した時は、差分で見せ、採用するかを選びます。

#### 説明文とタグの案

ボタンを押すと、本文から`description`と`tags`の候補を出します。タグは、ほかの記事ですでに使っているタグを優先します。候補は記事の設定欄に並び、使うものを選びます。

#### 推敲

ボタンを押すと、直した方がいい箇所を一覧で返します。指摘ごとに直した案が付き、1件ずつ採用するかを選びます。本文を勝手に書き換えることはしません。公開ボタンを押した時にも、同じ確認を行えるようにします。

推敲の基準は、Nagori用に新しく作ります。見るのは次の4つです。

| 観点 | 例 |
|---|---|
| 誤字脱字と表記の揺れ | 変換の誤り、同じ記事の中で「ユーザー」と「ユーザ」が混じる |
| 読みやすさ | 長すぎる文、主語と述語のねじれ、意味が通りにくい文 |
| 事実の確認 | 日付、数字、固有名詞、技術的な説明の誤りらしきもの |
| 公開前の確認 | 書きかけの段落、TODO、住所や電話番号などの個人情報らしきもの |

事実の確認は、AIがWebで調べられないと、古い知識で誤りと判断するおそれがあります。`agy`が許可なしでWeb検索を使えるかを確かめ、使えない場合は指摘に「AIの知識による」と添えて断定しない形にします。

#### 見た目の変更

チャットで「もっと柔らかい雰囲気に」などと頼むと、AIが`theme.css`の変更案を返します。アプリは、変更案が`theme-contract.md`にない変数やクラスを使っていないかを確かめます。そのうえでプレビューに試しに当てて見せ、採用すると`theme.css`に保存します。

書き換える前の`theme.css`は履歴として残し、アプリの画面から戻せるようにします。`theme.css`をアプリの外で書き換えた場合も、再起動せずにプレビューへ反映します。

### 5. グラフビュー

左の欄の「ゴミ箱」の下にある「グラフビュー」を押すと、本文の場所に記事とタグのグラフを表示します。もう一度押すか、記事の点やファイル一覧から記事を開くと、エディタに戻ります。編集中の本文、Undo履歴、自動保存は保たれます。

`src/content/blog`のMarkdownを記事の点にし、Front Matterのtitleを名前に使います。titleがなければファイル名を表示します。tagsは別の色の点になり、記事と線でつながります。解決できる相対リンクと`/posts/<slug>`のブログ内リンクも線で結びます。Front Matterのslugがあれば使い、なければ記事のパスから拡張子と末尾のindexを外して解決します。同じslugの記事が複数あるリンクは線を作りません。`[[ファイル名]]`のリンクも解決します。

点は力学のシミュレーションで広がり、ドラッグした後もなめらかに落ち着きます。背景のドラッグで全体を移動し、ホイールやピンチで拡大縮小できます。カーソルを合わせるとつながりを強調し、名前は拡大した時に表示します。ファイルの変更は点の位置を保って反映し、動きが落ち着くとシミュレーションと描画を止めます。矢印キーで点を選び、Enterで記事を開けます。プラスとマイナスのキーでも拡大縮小できます。

## 作る順番

| 段階 | 内容 |
|---|---|
| 1 | 1つのNagoriでフォルダを判定し、ブログのリポジトリを開いて記事を書ける |
| 2 | 本文内のFront Matterをプロパティとして表示 |
| 3 | プレビュー |
| 4 | GitHubへの反映 |
| 5 | AI。チャット、説明文とタグの案、推敲、見た目の変更 |

新しい記事は今までどおり`npm run new-post`で作成します。段階4ではターミナルでのpushを置き換えます。AIはプレビューができてからでないと見た目の変更を確かめられないので、最後にします。

## 決めていないこと

| 項目 | 内容 |
|---|---|
| `agy`の作業フォルダ | 作業フォルダを指定する方法が公式の資料にない。空の作業用フォルダで起動する案 |
| `agy`のWeb検索 | 許可なしで使えるか、検索だけ許可できるか |
| 推敲の基準の中身 | 4つの観点ごとの具体的な決まり |
| 編集画面の見た目 | 書いている画面にも`theme.css`の色や字体を反映するか |
| 署名 | 自分用なのでad-hoc署名で足りる見込み |
