# Nagori仕様書

改訂版1.24、2026-10-09

## 1. 目的と対応環境

Nagoriは、ローカルのMarkdown記事を書くmacOS向けエディタ兼プレビューアである。Markdownをそのまま保存し、表示を切り替えたり閲覧したりしても本文を変えない。

初回公開版はApple SiliconのmacOSを対象とする。最低対象はmacOS 13。WindowsとLinuxは対象外。実装にはTauri 2、Rust、Svelte 5、TypeScript、Vite、CodeMirror 6を使う。

## 2. ワークスペースとファイル

同時に扱うワークスペースと中央に表示するファイルはそれぞれ1つとする。タブと複数ウィンドウは設けない。前回のワークスペースと記事を次回起動時に開き、メニューから別のフォルダを開ける。

File Treeはフォルダを先に並べ、その後に各名前順で表示する。`.git`と`node_modules`は一覧・検索・監視から除き、シンボリックリンクは辿らない。

記事とフォルダの作成・名前変更に対応する。ファイルやフォルダをワークスペース内でドラッグして移動できる。移動先に同じ名前がある時は移動しない。名前変更や移動ではMarkdown内のリンク・画像参照を書き換えない。ワークスペースの外への移動にはFinderを使う。

サイドバーには「すべてのノート」「スター付き」「最近見たノート」「ゴミ箱」を表示する。すべてのノートは名前順、スター付きはスターを付けた順、最近見たノートは更新日時と最終閲覧時刻の新しい方で並べる。最近見た件数は設定で10〜50件に変えられる。

ゴミ箱へ移したファイルやフォルダはアプリ内で元に戻せる。「完全に削除」と「ゴミ箱を空にする」はmacOSのゴミ箱へ移す。保存期限は7日、14日、30日、60日、90日、無期限から選べる。

## 3. 対応ファイル

| 種類 | 扱い |
|---|---|
| `.md`、`.markdown` | Markdownとして編集・プレビュー |
| UTF-8のテキスト | プレーンテキストとして編集 |
| PNG、JPEG、GIF、WebP | 画像プレビューと記事への挿入 |
| その他 | 編集対象外 |

MarkdownとテキストではBOMとLF / CRLFを保持する。不正なUTF-8、混在改行、上限を超える文書は編集しない。画像はSVGを含めない。

## 4. 編集とプレビュー

Live Previewではカーソルや選択範囲に応じてMarkdown記号を見せ、装飾を表示する。Previewは読み取り専用で、検索・選択・コピーを使える。編集対象のMarkdownは見出し、リスト、タスクリスト、引用、表、フェンスコード、リンク、画像、LaTeX数式を扱う。未対応の記法も原文を保持する。

選択時のツールバーとメニューから太字、斜体、取り消し線、リンク、インラインコードを使える。ツールバーの箇条書きと番号付きリストのボタンは、選択が触れるすべての行をリストにする。空行と空白だけの行は飛ばし、番号付きは上から順に番号を振る。選んだ行がすでに同じ種類のリストなら記号を外して元に戻す。違う種類のリストが混ざる時は、押した方の種類にそろえる。見出しと引用の記号は外してからリストにする。選択に表、コードブロック、数式、Front Matterが触れる時は変換しない。変換後は変換した行全体を選ぶ。本文の右クリックメニューから見出し、リスト、引用、表、区切り線、画像を挿入できる。見出し、リスト、引用は右クリックした位置に記号を入れ、行の途中なら改行してから入れる。表と区切り線は前後に空行を入れて置く。選択した文字は書き換えない。挿入は1回の取り消しで戻せる。本文ヘッダーに記事操作メニューは置かない。

リスト項目ではTab / Shift＋Tabで字下げを変更する。表は、カーソルが中にあっても表の見た目のまま編集できる（設定「表を見た目のまま編集する」がオンの時）。各マスは独立した編集欄になり、クリックするとそのマスの中身をMarkdownの原文のまま編集できる。ほかのマスは装飾つきで表示する。マスを離れると、そのマスは装飾つきの表示に戻る。マスの内容は表全体のMarkdownとして本文へ書き戻すが、編集したマス以外の記法と空白は変えない。1回の入力のまとまりが、本文の1回の取り消しになる。Tabで次のマス、Shift＋Tabで前のマスへ移る。最後のマスでTabを押すと、下に行を追加して、その行の最初のマスへ移る。Enterは下のマスへ移り、最後の行では行を追加する。変換中のEnterは変換の確定に使い、移動も追加もしない。矢印キーは、マスの文字の端にいる時だけ隣のマスへ移る。表の上端と下端から外へ出ると、本文のカーソルを表の前後の行へ移す。Escapeでマスの編集をやめ、本文のカーソルを表の直後へ移す。Cmd＋Enterで下に行を追加し、Cmd＋Option＋→と←で右と左に列を追加する。マスの上の右クリックメニューから、行と列の追加、行と列の削除、表の削除ができる。見出しの行は削除できず、見出しの上には行を追加できない。列が1つだけの表では列を削除できない。追加したマスは空のまま保存し、空白は入れない。表を挿入した直後は、見出しの最初のマスへ入る。設定がオフの時は、カーソルが表の中にある間は表の記法を開いて編集する。Previewでは表を読み取り専用で表示する。対応するコードフェンスには言語別の色分けを付ける。LaTeX数式はMathJaxで表示し、必要な資産はアプリに含める。

表の列の幅は、見た目のまま編集がオンの時、見出しの行の右端をドラッグして変えられる。つまみは最後の列を除く各列の右端に出て、隣の列との境目を動かす。幅は区切り行の `-` の数で覚える。`-` の数の比が列の幅の比になり、揃えの `:` は保つ。全列の `-` の数が同じ（既定の `---` など）時は、内容に合わせた自動の幅で表示する。ドラッグの間は表示だけを変え、マウスを離した時に区切り行を1回書き換える。この書き換えは本文の1回の取り消しになる。`-` の数は各列3以上にし、比の合計は約60にそろえる。列の最小幅は表示上48pxとする。見た目のまま編集がオフの時とPreviewでは、つまみを出さず、区切り行の比に従う幅で表示する。行と列の追加・削除では既存の列の `-` の数を保ち、追加した列は `---` にする。TabやEnterで表を整えても、区切り行の `-` の数は変えない。

画像は貼り付け、Finderからのドロップ、右クリックメニューから挿入する。記事と同じフォルダの`assets`へコピーし、相対パスを記述する。元画像と同名の画像を上書きしない。

見出し1〜4があるMarkdown記事では目次を表示する。目次の項目を選ぶと記事内の見出しへ移動する。表示の切り替えと幅は保存される。集中モードはカーソル周辺以外を薄く表示する。タイプライター表示はキー操作によるカーソル移動後に行を中央付近へ寄せる。両方とも設定に保存する。

## 5. 編集の安定性

Live Previewでは、カーソルや選択が要素に触れていない時に記号を隠し、触れている時に記号を見せる。入れ子の要素では親の記号も見せ、選択が複数の要素にまたがる時は交差するすべての要素の記号を見せる。記号の表示を切り替えても、カーソルの文書上の位置、選択範囲、本文は変えない。

記号を見せる単位は次のとおり。

| 対象 | 単位 |
|---|---|
| 太字、斜体、取り消し線、リンク、インラインコード | インライン要素全体 |
| ATXの見出し | 見出し行 |
| Setextの見出し | 本文と下線を含む見出し全体 |
| 引用、リスト、タスクリスト | カーソルや選択がある行の記号。親の構造は保つ |
| コードブロック、表、数式、画像 | 要素全体。表は編集時にMarkdownソースを見せる |

日本語IMEの変換中は、変換範囲を置換も非表示もしない。選択時のツールバーは出さない。自動保存は待ち、確定後に予約する。記事の切り替えと終了は、変換が確定かキャンセルされた後に保存へ進み、途中の文字列を捨てない。

Previewは閲覧専用で、カーソルや選択が触れても記法を見せない。本文入力、貼り付け、切り取り、Undo・Redoによる本文変更、書式、タスクのチェック、画像挿入は無効にする。検索、選択、コピー、スクロール、外部変更の再読み込みは使える。

## 6. 検索と移動

Quick Openはファイル名とパスを検索し、空欄では最近開いたファイルを表示する。Cmd＋Fで記事内を検索し、大文字小文字と正規表現を切り替えられる。置換は1件ずつ、または一括で行い、一括置換は1回のUndoで戻せる。

Cmd＋Shift＋Fでワークスペース内のMarkdownとテキスト本文を検索する。`.git`、`node_modules`、シンボリックリンク、2MiBを超えるファイルは対象外。結果は最大500件、1ファイル50件まで。検索結果から記事を開くと、一致箇所を選択して表示する。

## 7. 保存と外部変更

編集後は設定した時間が経つと自動保存する。初期値は0.5秒。Cmd＋Sで手動保存する。IME変換の確定を待って保存し、記事やワークスペースの切り替え、終了の前にも保存を完了する。

保存失敗、外部変更との競合、外部削除が起きた時は本文を保持して自動保存を止める。再読み込み、再試行、明示上書き、別名保存、破棄して閉じる操作を提示する。

Live PreviewとPreviewの切り替えは本文、保存状態、Undo履歴を変えない。未編集箇所の記法、空白、末尾改行を自動整形しない。クラッシュや強制終了後の未保存内容復元、版履歴、バックアップは行わない。

## 8. 設定と画面

設定はアプリの`settings.json`に保存する。設定画面ではテーマ、本文の文字サイズ・幅・幅の自動調整・行間・字体、拡大縮小で文字サイズを変えるか、自動保存までの時間、記事を開いた時の表示、集中モード、タイプライター表示、見出しの下線、最近見たノートの件数、目次、ゴミ箱の保存期限を変更する。拡大縮小をオンにすると、Cmd＋・Cmd－・Cmd＋0と、トラックパッドのピンチで本文の文字サイズを1pxずつ変え、Cmd＋0で既定値の19pxに戻す。表示メニューからも同じ操作ができる。

「本文の幅を自動で調整する」をオンにすると、本文の幅は、ウィンドウの幅から表示中のサイドバーと目次、本文の左右の余白を引いた空きに合わせる。幅は560pxから1000pxの範囲に収め、目次を閉じると本文が広がり、開くと狭まる。目次を出せるかは、本文の最小幅560pxで判断する。オンの間は「本文の幅」のスライダーを無効にし、手動で設定した幅の値は変えない。オフに戻すと、手動の幅に戻る。

本文の下に状態バーは置かない。現在の記事名と保存状態は上部に表示し、Markdownとテキストでは文字数を本文ヘッダーに表示する。上部バーからQuick Open、テーマ切り替え、サイドバー表示を操作する。

## 9. 性能の目標

性能はReleaseビルドで測る。測定用のワークスペースは1,000ファイルで、100KiBの日本語を含むMarkdownを編集対象にする。起動時にネットワークは使わない。

- 起動から本文を入力できるまでを2秒以内にする。
- 通常の入力から画面に反映されるまでを、95パーセンタイルで50ms以内にする。
- Quick Openの検索更新を、95パーセンタイルで100ms以内にする。
- 画像を表示せず起動して30秒たったIdleのメモリは、アプリとWebView関連のプロセスの合計で測り、100MiB以下を努力目標にする。配布の条件にはしない。現在の値は[メモリ調査](performance/memory.md)に記録する。
- 日本語IME、表の切り替え、画像を含む記事で、目に見える入力の停止を出さない。
- 全ファイルの本文を事前に索引化しない。測定で問題が出た箇所だけを直す。

## 10. ファイルアクセスの安全性

ファイル操作は選択中のワークスペース内に限る。フロントエンドとRust側の両方でパスと名前を検証する。Markdown内のHTML、JavaScript、イベントハンドラーは実行せず、外部画像を自動取得しない。

外部リンクはHTTP / HTTPSだけを既定のブラウザーで開く。ローカルリンクはワークスペース内のMarkdownだけを開く。

## 11. 対象外

| 分野 | 対象外の機能 |
|---|---|
| 対応環境 | Windows、Linux、タブ、複数ウィンドウ |
| ノート管理 | AI、タグ管理、Graph、Backlink、Database、Canvas、プラグイン、同期、公開、共同編集 |
| 復元 | 版履歴、バックアップ、クラッシュ後の未保存内容復元 |
| 取り込み・編集 | 画像以外の外部ドラッグ＆ドロップ、外部画像の自動取得、画像サイズ編集 |
| Markdown | リンク・画像参照の自動更新、脚注、Obsidian独自拡張、HTML貼り付けの変換 |
| 検索・配布 | 複数ファイルにまたがる置換、差分表示、自動マージ、ストア配信、自動更新 |
