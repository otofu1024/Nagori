# Nagori MVP 仕様書

改訂版1.10、2026-10-05

## 1. 目的

アプリ名は **Nagori** とする。

ブロガーが、既存のフォルダにあるMarkdown記事を、読みやすい表示で快適に編集できる軽量なデスクトップアプリを作る。

MVPでは、次の一連の作業を成立させる。

1. プロジェクトフォルダを開く。
2. 記事を探して開く、または新しい記事を作る。
3. 日本語を含む文章をLive Previewで編集する。
4. ローカル画像を挿入する。
5. 編集内容を安全に保存する。

AIによる構成整理・論理レビュー・校正・タグ分類は将来の検討対象とし、MVPの設計に専用の拡張機構は作らない。

## 2. 対応環境・技術構成

- MVPの対応・試用環境：macOSのみ。
- Windows：将来対応。MVPでは実装・配布・検証の対象に含めない。
- Linux：MVP対象外。
- 技術構成：Tauri 2、Rust、Svelte、TypeScript、Vite、CodeMirror 6。
- 将来のWindows対応を見据えてTauriを採用する。OS固有のファイル操作はTauri・Rust側で扱い、Windows専用処理は必要になった時点で追加する。
- 開発開始時に依存バージョンを固定する。
- 初回のローカル試用はApple Silicon（arm64）。バンドルの最低OS設定はmacOS 13、フロントエンドはSafari 16を対象にビルドする。確認環境はmacOS 26.6.2 / arm64であり、過去のmacOSやIntelでの動作確認済みという意味ではない。
- macOSでインストールまたは展開から起動できる配布物を用意する。ストア配信・自動更新はMVP対象外。

## 3. 文書の基本原則

- 文書の正本はMarkdownテキストとする。
- Live Previewは表示上の加工とし、表示切り替えだけでは本文・保存状態・Undo履歴を変更しない。
- 編集していない箇所の記法・空白・末尾改行を自動整形しない。
- 未対応の記法も原文を保持し、テキストとして編集できる。
- 読み込みに失敗した内容、保存に失敗した内容を、成功したものとして扱わない。

## 4. Workspace

### 4.1 プロジェクトの選択

- アプリは、選択された1つのフォルダをプロジェクトとして扱う。
- 初回起動時はフォルダ選択画面を表示する。キャンセル時は同じ画面にとどまる。
- 次回起動時は、前回のプロジェクトと最後に開いていたファイルを開く。
- 前回のフォルダが存在しない、またはアクセスできない場合は、理由を表示してフォルダ選択画面へ戻る。
- メニューから別のプロジェクトを開ける。
- 同時に開くプロジェクトは1つ、中央に表示するファイルも1つとする。タブ・複数ウィンドウは実装しない。
- プロジェクト切り替え前に、現在の編集内容の保存を完了する。保存失敗・競合時は切り替えを停止する。
- 前回のプロジェクト、最後のファイル、テーマ、フォントサイズはアプリ設定として保持する。クラッシュ時の本文復元は行わない。

### 4.2 File Tree

- 左サイドバーにファイル・フォルダを表示する。
- フォルダの展開・折りたたみに対応する。
- フォルダを先に、その後ファイルを名前順に表示する。大文字小文字を同一視する並びでは、元の名前で順序を確定する。
- 初期状態では `.git` と `node_modules` 配下を表示・検索・監視の対象から除外する。その他のドットで始まるファイル・フォルダは表示する。
- ファイル内容や画像を、ツリー表示のために一括読み込みしない。
- 外部から追加・削除・名前変更された項目をツリーへ反映する。
- 選択中のファイルと、中央で開いているファイルを識別できるようにする。
- 「Finderで表示」を用意する。

### 4.3 作成・名前変更

- Markdownファイルとフォルダを作成できる。
- ファイル・フォルダのInline Renameに対応する。Enterで確定、Escapeでキャンセルする。
- 名前変更前に、その操作の影響を受ける編集中ファイルを保存する。保存できなければ操作を停止する。
- 成功後に、開いているファイル・最近開いたファイルのパスを更新する。
- 空の名前、区切り文字、`.`・`..`、OSで使用できない名前は拒否する。
- 既存項目と衝突する場合は上書きせず、入力欄に理由を表示する。
- 大文字小文字だけを変更する名前変更も、対応OSで確認する。
- 名前変更によるMarkdown内のリンク・画像パスの自動更新は行わない。操作入口にその旨を表示する。
- プロジェクトのルート自体の名前変更・削除は、アプリ内では行わない。
- シンボリックリンク・ジャンクションは表示のみとし、MVPでは辿らず、編集・名前変更・削除の対象にしない。

### 4.4 削除

- 選択したファイル・フォルダをmacOSのゴミ箱へ送る。
- 通常の削除確認ダイアログは表示しない。
- フォルダ削除も配下を含めてゴミ箱へ送る。コンテキストメニュー上でフォルダ削除であることを明示する。
- 削除前に、その操作の影響を受ける編集中ファイルを保存する。保存失敗・競合時は削除を停止する。
- 削除成功後は対象への保存予約を解除する。開いているファイルが含まれる場合は、中央を未選択状態にする。
- 削除結果と対象名を通知する。復元はOSのゴミ箱で行い、アプリ独自の削除Undoは実装しない。
- ゴミ箱へ送れない場合は失敗を表示する。完全削除へ切り替えない。

### 4.5 MVP対象外のファイル操作

- 内部Drag & Dropによる移動。
- 外部ファイル・フォルダのDrag & Dropによる取り込み。
- 複数項目の一括操作。

画像の取り込みは、§8の「画像を挿入」と画像の貼り付けで対応する。その他の移動・取り込みはFinderで行う。

### 4.6 ターミナルから開く

- macOSの`nagori`コマンドで、指定先を現在または新規起動したNagoriに渡す。
- アプリメニュー（Nagori）の「nagoriコマンドを登録…」「nagoriコマンドの登録を解除」で、`nagori`コマンドを登録・解除できる。Workspaceを開いていなくても利用できる。
- 起動スクリプトをアプリに同梱する。Applicationsへ置いたアプリから、`/usr/local/bin/nagori`にリンクを登録する。必要な場合はmacOSの管理者認証を使う。既存の別コマンドを上書きせず、登録解除も現在のアプリのリンクに限定する。
- 結果と失敗理由を通知で表示する。日本語変換中とファイル処理中は実行しない。
- `nagori .`と引数なしは現在のフォルダをWorkspaceとして開く。
- `nagori test.md`は現在のフォルダをWorkspaceにし、対象ファイルを選択する。配下の相対パス・空白や日本語を含むパスにも対応する。
- 現在のフォルダ外のファイルは、その親フォルダをWorkspaceにする。存在しない対象は作成しない。引数は1件までとする。
- 起動時の指定先は前回Workspaceの復元より優先する。起動後の切り替えは既存の保存・IME待機・競合確認を通し、保存できなければ現在の本文を保持して停止する。
- コマンドはmacOS標準の起動要求を送り、アプリ内の読み込み完了までは待たない。Windows用のコマンドは将来対応時に検討する。

## 5. ファイルの扱い

| 種類 | MVPでの扱い |
|---|---|
| Markdown：`.md`、`.markdown` | Live Previewで編集 / Previewで閲覧 |
| 画像：PNG、JPEG、GIF、WebP | 中央で画像プレビュー |
| その他のファイル（JSON、コード、テキストなど） | テキストとして開ける場合は、等幅のプレーンテキストとして編集。Live Preview・装飾・画像挿入・Preview切替・シンタックスハイライトは使わない。テキストとして開けない場合は理由とFinderで表示する操作を提示 |

- 拡張子の判定は大文字小文字を区別しない。
- Markdownとその他のテキストの文字コードはUTF-8に限定する。UTF-8 BOMがある場合は保持する。
- その他のファイルは、ツリーの表示では中身を読まず、開く時に判定する。NUL文字を含むものはテキストではないとして開かない。
- その他のテキストも、自動保存・保存失敗・外部変更と競合・別名保存をMarkdownと同じ規則で扱う。Markdownの別名保存はMarkdownの拡張子に限り、その他のテキストは画像の拡張子以外の名前へ保存できる。
- 不正なUTF-8は代替文字へ変換して編集せず、非対応として理由を表示する。
- 既存ファイルのLF / CRLFを保持する。新規ファイルはLFを使う。改行形式が混在するファイルはMVPでは編集対象外とし、理由を表示する。
- 初期のMarkdown・テキストの編集上限は2MiBとする。上限を超えるファイルは理由を表示し、読み込み・編集しない。
- 画像プレビューはファイルサイズ20MiB以下、画素数1,600万以下を対象とする。上限超過・破損時は理由を表示する。
- 上限は実測に基づきリリース前に見直せるが、変更後の値を仕様とUIに反映する。
- 読み取り専用ファイルは閲覧できるが、編集操作を無効にする。編集中に権限が変わった場合は保存失敗として扱う。

## 6. Markdown対応

### 6.1 基準

CommonMarkを基本とし、GFMのTable、Task List、Strikethroughを追加する。GitHub上の表示全体との完全一致は保証しない。

対応対象：

- Heading：ATX / Setext。
- Bold、Italic、Strikethrough。
- Link：インライン形式、参照形式、CommonMarkのAutolink。
- Quote。
- Inline Code。
- Code Block：フェンス形式、インデント形式。
- Ordered List、Unordered List、ネストしたリスト。
- Task List。
- Table。
- Image。
- LaTeX数式：インライン・表示式。
- Thematic Break：水平線。
- CommonMarkのSoft / Hard Line Break。

GFMの拡張Autolink、脚注、Obsidian独自拡張はMVP対象外とし、原文を保持する。

### 6.2 特殊な内容

- Raw HTMLはソースとして表示し、HTMLとして実行・描画しない。
- 文書先頭の `---` で囲まれたFront Matterは、生テキストのブロックとして表示・編集する。メタデータ専用UIや値の解釈は行わない。
- Front Matterとして認識する範囲は、文書先頭の `---` 行から次の `---` 行までとする。閉じる行がなければ通常のMarkdownとして扱う。
- 未対応・未完成の記法は、編集可能なソース表示を優先し、無理に置換しない。
- Code Blockは等幅フォントと背景で区別する。言語別Syntax HighlightingはMVP対象外。

### 6.3 LaTeX数式

- 既存Markdown内の学術的な数式を読む用途としてMathJaxを採用する。数式専用の入力UIは作らず、独立したLaTeX文書のコンパイルは行わない。
- インラインは `$...$` / `\(...\)`、表示式は `$$...$$` / `\[...\]` に対応する。
- MathJax 4.1.3のbase・ams・newcommand・mathtoolsで、分数・総和・積分・添字・行列・場合分け・複数行の式を描画する。同じ記事内の式番号、\tag、\label、\ref／\eqref、\newcommandに対応し、前方参照も解決する。記事間でマクロ・番号・ラベルを引き継がない。未定義の参照はMathJaxの「??」表示になる。
- 単一 `$` は開き直後・閉じ直前に空白を許可せず、閉じ直後が数字の場合も数式としない。通貨の曖昧な `$` は `\$` でエスケープする。
- コード・Raw HTMLブロック・Front Matter内の記法は数式として解釈しない。
- 未完成・不正・未対応の式は原文を保持する。描画エラーは原文と「数式エラー」、詳細を示す。
- 数式から任意のHTML・外部画像・外部スクリプトを読み込まない。`\mmlToken`の任意リンク・CSS・フォント属性は拒否する。拡張の自動取得は行わない。1式8,192文字、記事全体512式・式本文合計262,144文字を上限とする。文字数はJavaScriptの文字列長で数える。マクロ展開・テンプレート置換は各1,000回、明示的な寸法指定は絶対値20em以下に制限する。上限超過時も原文を保持する。
- MathJaxは数式を表示する時に読み込む。フォントなどの必要資産をアプリへ同梱し、表示のための外部取得は行わない。一度読み込んだエンジン・フォントモジュールは実行環境に残るが、記事ごとの描画文書・マクロ・不要な結果への参照は解放する。
- 記事の切り替え・本文更新で古い数式の結果を反映せず、閉じた記事の描画結果を保持し続けない。
- ライブラリの採用理由は対応範囲と既存記事との互換性。省メモリ性・入力性能はMac実機での測定前に達成済みとしない。

## 7. Live Preview

### 7.1 原則

**読むときはレンダリング結果、触るときはMarkdown。**

- カーソル・選択が要素に触れていない場合、対応する記号を隠して装飾表示する。
- 要素のソース範囲内にカーソルがある、または選択範囲がそのソース範囲と交差する場合、記号を表示する。
- 要素のソース範囲には開閉記号を含める。カーソルがその開始位置・終了位置にある場合も表示対象とする。
- 入れ子では、対象を含む親要素の記号も表示する。
- 選択が複数要素にまたがる場合、交差するすべての要素の記号を表示する。
- 記号を表示しても、可能な範囲で太字・斜体・見出しなどの装飾を維持する。

### 7.2 表示を切り替える単位

| 対象 | 記号を表示する単位 |
|---|---|
| Bold / Italic / Strikethrough / Link / Inline Code | インライン要素全体 |
| ATX Heading | 見出し行 |
| Setext Heading | 本文と下線を含む見出し全体 |
| Quote / List / Task List | カーソル・選択がある行の記号。親のリスト・引用構造は維持 |
| Code Block | ブロック全体。内容は常時テキスト表示 |
| Table | 表全体。編集時はMarkdownソース |
| LaTeX数式 | 式全体。複数行表示式はブロック全体 |
| Image | 画像要素全体。編集時は記法、通常時は画像 |
| Thematic Break | 該当行 |

- 表のセル編集UIや画像のサイズ編集UIは作らない。
- Task Listのチェックボックスをクリックすると、対応する `[ ]` / `[x]` を切り替える。この変更はUndo可能な本文編集として扱う。
- 画像・表などの表示をクリックすると、対応するソース位置へカーソルを移し、編集できるようにする。
- 通常のリンククリックは編集操作とする。Cmd＋クリックで、許可された外部リンクを開く。

### 7.3 編集の安定性

- 本文の選択はブラウザ標準の表示とテーマの色を使い、複数行でも本文の列の外側にある左右の余白を塗らない。ライト・ダーク、Live Preview・Preview・テキストファイルで共通とする。
- 空行は通常の本文行と同じ行高にし、改行直後と入力後でカーソルの高さがずれず、空行を通るカーソル移動でも後続の本文が上下に動かないようにする。
- Live Preview・Preview・テキストファイルでは、本文の表示領域の高さの半分を末尾の余白とし、最後の行を画面の中央付近までスクロールできる。
- 本文の領域の内側に縦スクロールバーの幅を常に確保し、出現・消失によって本文の幅と位置が変わらないようにする。Live Preview・Preview・テキストファイル・目次表示時で共通とする。
- 本文・ファイル一覧・目次のスクロールバーは、ふだんはつまみと溝を透明にする。その領域でマウスを動かした時と、キーボード・トラックパッドなどで実際にスクロールした時だけ、細い角丸のつまみを表示する。動きが止まって1秒後から240msかけて消す。マウスを乗せたままでも消え、ドラッグ中のつまみは表示を保つ。OSの「視差効果を減らす」を有効にした場合は、1秒後に遷移なしで消す。
- スクロールバーの領域は8px、透明な縁を除くつまみは6pxとし、溝は表示中も透明にする。つまみの色は各テーマのmutedを使う。macOSの「スクロールバーを常に表示」でも同じ条件で表示する。scrollbar-gutter: stableを保ち、縦の領域を常に確保して文書の長短でも本文の幅を保つ。
- 記号の表示切り替えで、カーソルの文書上の位置や選択範囲を変えない。
- レイアウトが変わっても、編集中の位置が画面内に残るようにする。
- 日本語IME変換中は、変換範囲を置換・非表示にしない。Floating Toolbarを表示しない。
- IME変換中のAuto Saveは待機し、確定後に保存を予約する。
- ファイル切り替え・終了は、IME変換が確定またはキャンセルされた後に保存処理へ進む。途中の文字列を破棄しない。
- 表示モードはLive PreviewとPreviewの2つ。従来のソース表示モードは設けない。上部ボタンかCmd＋Shift＋Lで切り替える。
- Live Previewの編集動作は維持する。Previewは閲覧専用とし、カーソル・選択が触れても記法を表示しない。表・画像・数式を操作しても編集表示へ戻さない。未対応記法や描画エラーの原文は、従来どおり内容を保持して表示する。
- Previewでは本文入力、貼り付け・切り取り、Undo / Redoによる本文変更、Formatting、タスクのチェック、画像挿入を無効にする。検索・選択・コピー・スクロールと外部変更のReloadは使える。
- モード切り替えで本文・保存状態・Undo履歴を変更せず、元の選択とスクロール位置を保持する。日本語変換中とファイル処理中は切り替えない。

## 8. 画像

- Markdownの相対画像パスは、そのMarkdownファイルの所在フォルダを基準に解決する。
- ローカル画像の読み込みは、選択されたプロジェクト内に限定する。`../` を含んでも実際の参照先がプロジェクト内なら許可する。
- プロジェクト外の画像、シンボリックリンク経由の画像、未対応形式、見つからない画像は、参照先と理由を表示する。
- 外部URLの画像はMVPでは自動取得しない。記法・参照先を表示する。
- メニューに「画像を挿入」を用意する。編集中のMarkdownがある場合に利用できる。
- ファイル選択ダイアログで選んだ対応画像を、記事と同じフォルダの `assets` フォルダへコピーする。元ファイルは残す。
- `assets` がなければ作成する。同名ファイルは番号を付け、既存ファイルを上書きしない。
- 画像だけをコピーした状態で貼り付けると、その画像を記事と同じフォルダの `assets` へ `pasted-image.<拡張子>` として保存し、カーソル位置または選択範囲へ相対パスの記法を挿入する。同名ファイルがあれば番号を付ける。対応形式と上限は§5の画像プレビューと同じ。
- クリップボードに文字も含まれる場合は、通常のプレーンテキストの貼り付けを優先し、画像として取り込まない。読み取り専用、Preview、日本語変換中、ファイル処理中は貼り付けで画像を取り込まない。
- コピー成功後に、カーソル位置または選択範囲へ相対パスの画像記法を挿入する。空白や括弧を含むパスも正しく解釈される記法を生成する。
- コピー失敗時は本文を変更しない。挿入のUndoは本文だけを戻し、コピーした画像は削除しない。
- ファイル・フォルダの名前変更に伴う画像パスの自動更新は行わない。

## 9. Formatting・基本編集

### 9.1 Floating Toolbar

- 常設Formatting Toolbarは置かない。
- Markdown編集時、空でないテキスト選択に対してFloating Toolbarを表示する。
- 対象：Bold、Italic、Strikethrough、Link、Inline Code。
- ツールバー操作で選択範囲を失わず、操作後はエディタにフォーカスを戻す。
- 単一段落内の未装飾テキストを選択した場合、対応する記法で囲む。Bold・Italic・Strikethroughでは、選択範囲の前後の空白を除いてから囲む。
- 選択範囲が同じ種類の装飾要素の中に収まる場合、同じ操作でその装飾を解除する。
- 選択範囲が同じ種類の装飾要素にかかる場合は、かかった要素まで範囲を広げ、内側の同じ種類の記号を外してから、全体を1つの記法で囲み直す。例えば `about **Autumn** that` を選んでBoldにすると `**about Autumn that**` になる。
- 別の種類の装飾要素は、範囲の中に丸ごと入るか範囲を丸ごと含む場合だけ残して囲む。境界を部分的にまたぐ場合、装飾を含む範囲をInline Codeにする場合、複数段落の選択、囲んだ結果がCommonMarkで意図した装飾にならない場合は、操作を無効にする。無効である理由を確認できるようにする。
- Linkは従来どおり、装飾をまたぐ選択では無効にする。
- Inline Codeは単一行のみ対応し、本文にバッククォートがある場合も正しい区切りを使う。
- Linkは表示テキストとURLを入力する小さな入力UIを開く。既存リンク全体を選択した場合は編集する。キャンセル時は本文を変更しない。

### 9.2 基本操作

- Live PreviewではUndo / Redo、切り取り、コピー、貼り付け、全選択に対応する。Previewでは選択・コピーのみ有効とする。
- コピー・切り取りは、選択されたソース上のMarkdownテキストを対象とする。
- 標準の貼り付けはプレーンテキストとする。HTMLのMarkdown変換は行わない。画像だけをコピーした場合の貼り付けは§8に従う。
- Auto Save後も、現在のファイルのUndo履歴を保持する。
- ファイル切り替え・アプリ再起動後のUndo履歴保持はMVP対象外。
- 外部変更のReload時はUndo履歴をリセットする。外部変更前の内容に戻せるとは表示しない。
- リスト内でEnterを押すと同じ種類の項目を継続する。空の項目でEnterを押すとリストを終了する。Code Block内では通常の改行を行う。
- キーボードだけでFile Tree、Quick Open、検索、エディタ、メニュー・ダイアログを操作できるようにする。
- フォーカスを視覚的に示し、アイコン操作には説明を付ける。

主要ショートカット：

| 操作 | ショートカット |
|---|---|
| Quick Open | Cmd＋P |
| Find | Cmd＋F |
| Save | Cmd＋S |
| Bold | Cmd＋B |
| Italic | Cmd＋I |
| Link | Cmd＋K |

Undo / Redo等はmacOSの標準操作に合わせる。取り消し線・Inline Codeはメニューとツールバーから利用でき、専用ショートカットはMVPでは必須としない。

### 9.3 本文の右クリックメニュー

本文の右クリック、またはShift＋F10でTauriのネイティブメニューを開く。WebViewの標準メニューは表示しない。選択内の右クリックでは選択を保ち、選択外ではクリック位置へカーソルを移す。日本語の変換中は選択とフォーカスを変更しない。

| 項目 | 動き |
|---|---|
| 切り取り、コピー、貼り付け、すべてを選択 | macOSの標準編集操作を使う |
| 見出し1、見出し2、見出し3、本文 | 選択が触れる各行のATX見出しを付与・置換・解除する |
| 箇条書き、番号付きリスト、タスクリスト | 空でない各行の先頭に記号を付ける。全行が同じ種類なら外す。別の種類のリストは置換し、番号は1から振り直す |
| 引用 | 空でない各行の先頭に`> `を付ける。全行が引用なら外す |
| 表を挿入 | カーソル行の後ろに3列の見出し行、区切り行、空の2行を入れ、最初のセルの「列1」を選択する |
| 区切り線を挿入 | カーソル行の後ろに`---`を挿入する |
| 画像を挿入… | §8の画像選択と取り込みを使う |

標準編集の後と画像挿入の前に区切りを置く。見出しとリストはサブメニューにまとめる。リストと引用はインデントを保つ。見出し解除では末尾の閉じる記号も外す。選択の終端が次の行の先頭にある場合、その行は操作対象に含めない。

表と区切り線は前後の段落から空行で分離する。区切り線の直前には必ず空行を置き、Setext見出しになることを避ける。段落操作は1回のトランザクションで適用し、`userEvent`を`input.format`とする。直前の入力とUndoの単位を分け、1回のCmd＋Zで操作前へ戻せる。操作対象外の記法・空白・改行は変えない。

読み取り専用、Preview、日本語の変換中、ファイル処理中は編集を伴う全項目を無効にする。コピーとすべてを選択は残す。Markdown以外のテキストでは標準編集の4項目だけを出す。

カーソルや選択がコードブロック、Front Matter、数式ブロックに触れる場合、見出し・リスト・引用・表・区切り線を無効にする。判定は操作対象の行全体で行う。リスト・引用・表に触れる場合は、見出しと本文への変更も無効にする。メニューを開いた後に記事・本文・選択が変わった場合、古いメニューの段落操作と画像挿入は実行しない。

## 10. Navigation

### 10.1 Quick Open

- プロジェクト内のMarkdown・画像・その他のファイルを対象にする。テキストとして開けるかは開く時に判定する。
- ファイル名とプロジェクト相対パスをFuzzy Searchする。
- 空の検索では最近開いたファイルを表示する。検索時の最近開いた順による加点はMVPでは行わない。
- 同名ファイルを区別できるように、相対パスを表示する。
- キーボードで候補を選択・確定できる。Escapeで閉じ、元のフォーカスへ戻す。
- 現在のファイルの保存完了後に切り替える。保存失敗・競合時は現在のファイルを維持する。

### 10.2 Find

- 現在のMarkdownファイルのソーステキストを対象に、リテラル文字列検索を行う。
- 件数と現在位置を表示し、次・前の一致へ移動できる。
- 一致箇所を選択して画面内へ表示する。隠れていたMarkdown記号も、その選択に合わせて表示する。
- Escapeで検索UIを閉じ、エディタへフォーカスを戻す。
- 置換、正規表現検索、プロジェクト全文検索はMVP対象外。

## 11. 保存・外部変更

### 11.1 保存タイミングと状態

- Auto Saveを基本とし、最後の編集から500ms後に保存を開始する。IME変換中は開始しない。
- ファイル・プロジェクト切り替え時と正常終了時は、保存待ちの変更を即時保存し、完了を待つ。
- Cmd＋Sで、保存待ちの変更を即時保存できる。
- UIに「未保存」「保存中」「保存済み」「保存失敗」「競合」を表示する。色だけに依存しない。
- 本文の変更世代を区別する。保存した世代より新しい編集があれば、保存完了後も未保存として扱う。
- 同じファイルへの保存は直列に処理する。古い保存結果で新しい内容を上書きしない。
- 一時ファイルへ書き込んでから置き換える方式など、途中失敗で元ファイルを空にしない保存方法を使う。OSに応じた既存の仕組みを利用し、既存ファイルのアクセス権を不用意に変更しない。
- 成功扱いにするのは書き込み・置き換えが完了した後とする。停電時の永続化までは保証しない。

### 11.2 保存失敗

- 権限不足、容量不足、ファイル使用中、参照先消失などの失敗理由を表示する。
- エディタ内の本文とUndo履歴を保持し、「再試行」「別名保存」を提示する。
- 保存失敗時はファイル・プロジェクト切り替えと終了を停止する。
- ユーザーが明示的に未保存変更を破棄する場合だけ、破棄確認の後に切り替え・終了できる。これは通常の削除確認とは別の操作とする。
- 別名保存の保存先はプロジェクト内とし、既存ファイルを無断で上書きしない。成功後は保存先を現在のファイルにする。

### 11.3 外部変更と競合

- 最後に読み込んだ／保存したディスク内容を、比較の基準として保持する。
- ファイル監視に加えて、保存直前とアプリが再びアクティブになったときに、現在のファイルの内容を確認する。更新時刻だけで変更を判断しない。
- 自分が保存した内容と一致する通知は、外部変更として扱わない。
- 外部変更があり、未保存編集も保存中の処理もない場合は自動Reloadする。読み込み成功後に本文を更新し、可能な範囲でカーソル・スクロール位置を保持する。
- 外部変更の読み込みに失敗した場合は、現在の本文を保持して理由を表示する。
- 未保存編集がある場合、または保存直前に基準と異なる内容を検出した場合は、保存を停止して競合を表示する。
- 競合中はAuto Saveを停止し、ディスク側・編集中の内容を保持する。
- 選択肢は「最新のディスク内容を採用」「編集内容で上書き」「別名保存」とする。採用・上書きは、どちらの内容を失うか明示する。閉じた場合は競合状態を維持する。
- 競合の選択待ちにディスクが再変更された場合、最新内容を再取得し、古い内容に対する選択だけで上書きしない。
- 自動マージ・差分ビューはMVP対象外。
- 協調しない外部アプリとの同時書き込みを完全には排除できないため、保存直前の再確認で検出可能な競合を扱う。監視だけで無損失を保証したものとはしない。

### 11.4 外部での削除・名前変更

- 開いているファイルが外部で消えた場合、元のパスへのAuto Saveを停止する。
- 外部Renameを確実に追跡できない場合は、旧パスの消失として扱う。
- 現在の本文を保持し、状況を表示して「別名保存」「閉じる」を提示する。閉じるときに未保存変更があれば破棄確認を行う。
- 自動保存によって元のパスにファイルを作り直さない。

クラッシュ・強制終了時の未保存内容復元、履歴、バックアップはMVP対象外。

## 12. プレビューとファイルアクセスの安全性

- ファイル読み書き・名前変更・削除は、選択されたプロジェクト内に限定する。画像挿入元はファイル選択で明示された画像だけを読み込む。
- Rust側でもパスの範囲と名前を検証し、フロントエンドの判定だけに依存しない。
- `../` やシンボリックリンクでプロジェクト外へアクセスできるようにしない。
- Markdown内のHTML・JavaScript・イベントハンドラを実行しない。SVGはMVPの画像プレビュー対象に含めない。
- 外部リンクを開く対象はHTTP / HTTPSに限定し、明示操作でOSの既定ブラウザへ渡す。その他のスキームは開かない。
- ローカルMarkdownリンクは、プロジェクト内の対応ファイルなら保存処理を経て開く。プロジェクト外や未対応ファイルは理由を表示する。同一文書内アンカー移動はMVP対象外。
- プレビューコンテンツにアプリのファイル操作権限を与えない。Tauriの権限は必要な操作に限定する。

## 13. UI

- 左：File Tree。
- 中央：Editor / Image Preview / 未選択・非対応状態。
- Markdownの記事に見出し1〜4がある時は、本文の右に目次を表示する。初期幅は220pxで、中央の領域が1068px以上なら表示する。幅を変更した後も、目次と本文の左右余白128pxを除いて本文に720px以上残る時だけ表示する。画像・テキストファイル・未選択状態では表示しない。
- サイドバーと本文、本文と目次の境界線をドラッグして幅を変えられる。サイドバーは200〜420pxで初期値272px、目次は180〜360pxで初期値220px。境界線の左右4pxを当たり判定にし、マウスを乗せた時とドラッグ中はアクセント色の3pxの線と左右の矢印カーソルを表示する。
- 境界線のダブルクリックで初期値へ戻す。Tabで境界線へフォーカスを当て、左右の矢印キーで線を10pxずつ動かせる。読み上げには縦のseparatorと現在・最小・最大の幅を伝える。ドラッグでは本文のフォーカスを保ち、文字の選択を防ぐ。
- 本文の列には左右余白を含めて848pxを残し、足りない時は目次を先に隠す。サイドバーは画面に収まる幅へ一時的に縮める。サイドバーの最小幅200pxと本文の848pxを同時に確保できない1048px未満のウィンドウでは、目次を隠してサイドバーの最小幅を保つ。サイドバーを隠す既存の操作も使える。
- 幅はドラッグ終了時に1回だけsettings.jsonへ保存し、再起動時に復元する。矢印キーとダブルクリックでは操作ごとに保存する。ウィンドウを狭くして一時的に縮めた幅は保存しない。古い設定に幅の項目がなくても既定値で読める。Rust側でも読み込みと保存時に範囲を調べ、範囲外なら該当する幅だけ初期値へ戻す。
- 目次の項目は14.5px、行高1.65、見出し1は太さ600とする。階層ごとに14px字下げし、各項目の上下に8pxの余白を置く。「目次」のラベルは14px、太さ600とする。
- 目次はATXとSetextの見出しを階層に応じて字下げし、装飾の記号を外してリンクの表示テキストを残す。スクロール時は本文の上端以前にある最後の見出しを、アクセント色と左の細い線で示す。目次が長い時は目次だけをスクロールする。
- 目次をクリック、またはTabで選んでEnterを押すと、見出し行の末尾へカーソルを移し、見出しを本文の上端付近へスクロールして本文にフォーカスを戻す。Previewでも使え、選択は変えずスクロールする。読み上げには「目次」のナビゲーションと現在位置を伝える。
- 角丸を使い、Appleライクで少しポップな見た目にする。
- 2026-10-01に受領したユーザー提供のブランド・UIイメージを視覚基準とする。参考資料は `design/` に保存する。
- ユーザーが選択した範囲は既存2ペイン構成の色・余白・アイコン・浮動ツールバーの調整。白〜淡い青、濃紺の文字、ミント〜シアンのアクセントを使う。
- macOSタイトルバーの文字を隠し、ウィンドウ操作ボタンとブランドを同じ上部バーに収める。空いた領域からウィンドウを移動できる。
- 上部バーにブランド、Quick Open、保存状態、テーマ操作をまとめる。サイドバーを非表示にしても編集中のEditorを作り直さない。
- Starred、Trash一覧、タグ管理、全文検索はMVPに追加しない。検索の案内は現在実装するファイル名・パス検索と一致させる。
- 本文は装飾を抑え、読みやすい行間・余白・日本語表示を優先する。
- Light / Darkに対応する。初回起動時だけOS設定からテーマを決めて保存し、次回以降は保存済みテーマを使う。上部のボタンを押すだけでLight / Darkを直接切り替え、その選択を保存する。継続的なOS追従モードは設けない。
- 色・余白・角丸は共通のトークンで管理する。将来用のテーマ編集UI・テーマ拡張機構は作らない。
- 本文フォントサイズの初期値は19px。12〜32pxで変更でき、次回起動時も保持する。File Treeなどの主要UI文字は13〜14px、補助表示は11〜12pxを基本とする。
- 現在のファイル名、必要に応じた相対パス、保存状態を常に確認できるようにする。
- 初回起動、空フォルダ、ファイル未選択、読み込み失敗にも専用の表示を用意する。

## 14. Performance

### 14.1 測定条件

macOSの基準マシンを開発開始時に決め、OS、CPU、RAM、ビルド種別を記録する。性能判定はReleaseビルドで行う。Windowsの性能測定は将来の対応時に行う。

基本の測定用プロジェクト：

- 対象ファイル数：1,000。
- 編集対象：100KiBの日本語を含むMarkdown。
- 見出し・リスト・表・画像を含む代表的な記事を固定して使う。
- 起動時はネットワーク取得を行わない。

### 14.2 初期目標

- 起動から本文入力可能まで：基準環境で2秒以内を目標とする。
- 通常入力から画面反映まで：95パーセンタイル50ms以内を目標とする。
- Quick Openの検索更新：95パーセンタイル100ms以内を目標とする。
- Idleメモリ：画像未表示・起動後30秒経過時に、アプリと専用WebView関連プロセスを合計して測定する。100MiB以下は努力目標とし、達成を配布条件にはしない。
- Cold / Warm起動を区別し、複数回の測定値を残す。
- 日本語IME、表の表示切り替え、画像を含む文書でも、目視できる入力停止がないことを確認する。
- 編集上限付近のMarkdown、大量のファイル、上限付近の画像は別途確認する。上限内でも操作不能になる場合は、実装または対応上限を見直す。

必要以上の先読みや全ファイル内容の索引化を行わず、測定で問題が確認された箇所を改善する。

## 16. 受け入れ条件

以下をmacOSで満たしたとき、MVP完成とする。Windowsでの検証は将来の対応時に行う。

1. フォルダを開き、記事を作成・検索・編集・保存できる。再起動後、前回のプロジェクトを開ける。
2. 閲覧、Live Preview / Preview切り替え、手動保存だけでは、本文・記法・空白・改行形式・BOMを変更しない。
3. 対応Markdownを表示でき、未対応記法・Front Matterも原文を保持して編集できる。
4. 日本語IME、選択、コピー、貼り付け、Formatting、Undo / Redoで本文とカーソルが壊れない。Auto Save後もUndoできる。
5. 太字と斜体の入れ子、複数行選択、引用内リスト、未完成記法、表・画像の編集で、定義した表示単位に切り替わる。
6. 画像挿入で元ファイル・同名画像を上書きせず、生成した相対パスでプレビューできる。
7. 連続編集と保存が重なっても、古い保存で新しい編集を上書きせず、保存状態が実際の内容と一致する。
8. 読み取り専用、容量不足などの保存失敗時に本文を保持し、再試行・別名保存ができる。切り替え・終了で黙って失わない。
9. 未保存変更がない外部更新はReloadし、未保存変更がある外部更新は保存を止めて競合として扱う。自分の保存通知では競合にならない。
10. 外部で削除・名前変更されたファイルをAuto Saveで再作成しない。
11. 名前変更・ゴミ箱への移動が正常に動く。ゴミ箱への移動失敗を完全削除に切り替えない。削除したファイルを保存処理で再作成しない。
12. 不正なUTF-8、上限超過、破損画像、プロジェクト外参照、Raw HTMLを定義した方針で扱い、既存ファイルを破損させない。
13. キーボードで主要操作ができ、現在位置・保存状態・失敗理由を確認できる。
14. 固定した基準環境・データで性能を測定し、目標未達の項目と判断を記録する。入力停止など日常編集を妨げる問題は残さない。

## 17. 開発順序

1. CodeMirror 6で、Live Preview・日本語IME・選択・Undo・表／画像の切り替えを試作する。
2. 1ファイルの読み込み・保存・保存失敗・外部変更を実装し、データ保全を確認する。
3. Workspace、File Tree、Quick Open、作成・名前変更・ゴミ箱への移動を追加する。
4. 画像挿入、Formatting、テーマ、配布物を仕上げる。
5. macOSで受け入れ条件と性能を確認する。
