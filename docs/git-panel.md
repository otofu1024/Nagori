# Gitの欄 要件定義(案)

- 対象: Nagoriで開いたフォルダがGitのリポジトリの時に使う「Git」の欄
- 状態: 2026-10-16にユーザーのOK。右の欄を使う機能はグループにまとめる。pushが断られたらpullするかだけを聞く(ユーザーの指示)
- 決まっていること(2026-10-16にユーザーが選んだ)
  - 添削の欄(PR #85)はマージせず、開いたまま置いておく
  - ブログに限らず、Gitのリポジトリならどのフォルダでも使える
  - コミットの取り消しは、pushの前だけ履歴から消す。push済みのものは打ち消すコミットを作る

## 1. 目的

ターミナルを開かずに、Nagoriの中で書いた変更をコミットしてGitHubへpushする。間違えたコミットは1つ取り消せる。

大事にしたいことは次の3つ。

1. 元のエディタの画面を変えない。左の欄には手を入れない。
2. GitHubの履歴を壊さない。強制push(`--force`)はしない。
3. 何をコミットするか、いつpushするかは自分で決める。勝手にコミットやpushをしない。

## 2. 機能

### 2.1 作るもの

| 機能 | 何をするか | Gitのコマンド |
|---|---|---|
| 変更の一覧 | 変更、追加、削除、新しいファイルを、ファイルごとに出す | `git status --porcelain=v2 -z` |
| ステージ | ファイルごとに、コミットに入れるかを選ぶ。全部を入れる、全部を外す、もできる | `git add -- <ファイル>`、`git restore --staged -- <ファイル>` |
| コミット | メッセージを書いて、ステージしたファイルをコミットする | `git commit -m <メッセージ>` |
| push | 今のブランチを、追跡しているリモートへpushする | `git push` |
| pull | pushがGitHubの新しい変更で断られた時だけ、pullするかを聞く。pushはしない | `git pull --rebase --autostash` |
| 直前のコミットの取り消し | pushの前なら履歴から消す。push済みなら打ち消すコミットを作る | 下の2.2 |

### 2.2 直前のコミットの取り消し

| 直前のコミット | すること | 結果 |
|---|---|---|
| まだpushしていない | `git reset --soft HEAD~1` | コミットだけが消え、変更はファイルに残り、ステージした状態に戻る。メッセージを直してすぐコミットし直せる |
| push済み | `git revert --no-edit HEAD` | 打ち消すコミットが1つ増える。GitHubへ反映するにはpushが要る |

- 押すと、どちらになるかと、対象のコミットのメッセージを出して確かめる
- 次の時は押せない
  - コミットが1つもない、または最初のコミットしかない(pushの前の最初のコミットは消せない)
  - 直前のコミットがマージのコミット
  - push済みの取り消しで、まだコミットしていない変更がある(打ち消しが変更とぶつからないように)
- 打ち消しの途中でぶつかったら、`git revert --abort`で元に戻し、「ぶつかったため取り消せませんでした」と出す
- 取り消せるのは直前の1つだけ。続けて押すと、その前のコミットを同じ決まりで扱う

### 2.3 pushが断られた時のpull

- pushが、GitHubに新しい変更があるため断られた時(`fetch first`、`non-fast-forward`)だけ、欄の上に「GitHubに新しい変更があります」と出し、「pullする」と「pullしない」を選ばせる
- 「pullする」を選ぶと、`git pull --rebase --autostash`でGitHubの変更を取り込み、自分のコミットをその後ろへ付け直す。pushはしない。pushは、確かめてから自分でpushのボタンを押す
  - まだコミットしていない変更は、Gitが一時的に退避して、取り込んだ後に戻す
  - 本文の欄で保存していない変更は、先に保存する。取り込みで開いているファイルが変わったら、本文の欄を読み直す
- 取り込みでぶつかったら、`git rebase --abort`でpullの前の状態に戻し、「GitHubの変更とぶつかったため、取り込めませんでした。ターミナルで直してください」と出す
- 「pullしない」を選ぶと、何もしないで閉じる

### 2.4 作らないもの

- 自分から始めるpull、fetchの自動実行、ブランチの切り替えと作成、マージ、リベース(2.3のpullを除く)、stash
- 強制push
- 行ごとのステージ(ファイル単位だけ)
- コミットの履歴の一覧(直前のコミットのメッセージだけ出す)
- AIによるコミットメッセージの案

## 3. 画面

### 3.1 置き場所

- 右の欄に置き、目次と切り替える。左の欄には何も足さない
- 右の欄を使う機能(目次、Git、後で添削)は、上のバーの右端に1つのグループとしてまとめる
  - グループは、アイコンのボタンを横に並べ、1つの枠で囲んだ切り替え(セグメント)にする。アイコンの大きさは今の目次のボタンと同じ
  - 開いている機能のボタンは、差し色の淡い面で示す。開いている機能のボタンをもう一度押すと、右の欄を閉じる
  - 並びは目次、添削、Gitの順。添削はPR #85をマージした時に加わる
  - 右の欄の上に、開いている機能の名前を小さな見出しで出す
- 開いたフォルダがGitのリポジトリでない時と、MacにGitがない時は、Gitのボタンを出さない
- 欄の幅と開閉は、目次の欄と同じ仕組みを使う。幅を機能ごとに覚えるかどうかは、目次と同じ1つの幅にする

### 3.2 欄の中の並び

1. 上: 今のブランチの名前と、pushしていないコミットの数(例「main 2つ先」)。pushのボタン
2. コミット: メッセージの入力欄と「コミット」のボタン
3. ステージした変更: ファイルの一覧。各行に「外す」
4. 変更: ファイルの一覧。各行に「入れる」。見出しの横に「全部入れる」
5. 下: 直前のコミットのメッセージと「取り消す」のボタン

### 3.3 ファイルの行

- 左に状態の印(変更、追加、削除、新規、名前の変更)。印の色はNagoriのライトとダークに合わせる
- ファイル名を太く、フォルダの場所をその右に薄く出す
- 行を押すと、そのファイルを本文の欄で開く。削除したファイルは開けない
- 差分の表示は作らない

### 3.4 状態ごとの見た目

| 状態 | 見た目 |
|---|---|
| 変更なし | 「変更はありません」の1行 |
| 実行中 | 押したボタンが押せなくなり、その横に小さな回転の印。点滅しない |
| 失敗 | 欄の上に、Gitのエラーを短く1〜2行。閉じるボタン付き |
| pushできない(リモートが先に進んでいる) | 欄の上に「GitHubに新しい変更があります」と、「pullする」「pullしない」のボタン(2.3) |
| 追跡するリモートがない | pushのボタンを押せなくし、理由を「リモートがありません」と出す |

### 3.5 一覧の更新

- 欄を開いた時、ファイルを保存した時、Nagoriのウィンドウに戻った時、Gitの操作の後に読み直す
- 外のターミナルでの変更も、ウィンドウに戻った時に反映される

## 4. 動き

### 4.1 Gitの呼び方

- Macに入っている`git`を、Rust側から1回ずつ起動する。作業ディレクトリは開いたフォルダのリポジトリのルート
- 認証(GitHubのログイン、SSHの鍵、キーチェーン)は、Gitの設定をそのまま使う。Nagoriはパスワードやトークンを持たない
- 入力を求められて止まらないよう、標準入力を閉じ、`GIT_TERMINAL_PROMPT=0`を付ける。認証が要る時は失敗として「GitHubのログインが要ります。ターミナルで1回pushしてください」と出す
- pushには時間の上限(1分)を付ける
- ファイル名は`--`の後に渡し、オプションとして読まれないようにする

### 4.2 コミットの前

- 本文の欄で保存していない変更があれば、先に保存してからコミットする
- メッセージが空の時と、ステージしたファイルがない時は、コミットのボタンを押せない
- コミットの名前とメールは、Gitの設定をそのまま使う。設定がない時はGitのエラーを出す

### 4.3 安全のための決まり

- `--force`、`--no-verify`、`reset --hard`、`clean`は使わない
- フックは普段どおり動かす。フックで失敗したら、その出力を短く出す
- 取り消しの確認の文には、消えるか打ち消すかをはっきり書く

## 5. 確かめること

- Rustの単体テスト: 一時ディレクトリに作ったリポジトリで、状態の読み取り(日本語のファイル名、空白入りの名前、名前の変更)、ステージと外す、コミット、取り消し(pushの前、push済み、最初のコミット、マージのコミット、ぶつかった時)、push(ローカルのbareリポジトリをリモートにする)、断られた時のpull(取り込めた時、ぶつかって元に戻す時、コミットしていない変更がある時)
- 画面の確認ページ: ボタンの出し分け(Gitのフォルダとそうでない時)、一覧、ステージ、コミット、取り消しの確認、エラーの表示を、ライトとダークで確かめる
- 試用のアプリで、ブログの写しを使って実際にコミットとpushと取り消しを試す。ユーザーのブログ`~/yuzu_notes`とGitHubの本物のリポジトリには触らない

## 6. レビューで決めたこと

| 項目 | 決めたこと |
|---|---|
| pull | pushがGitHubの新しい変更で断られた時に、pullするかを聞く |
| 差分の表示 | 作らない。必要になったら次に足す |
| 新しいファイルの扱い | 一覧に出し、ほかと同じく自分で入れる |
| 取り消しの後の状態 | ステージした状態に戻す(`--soft`) |
