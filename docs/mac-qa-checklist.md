## 共通準備

通常のNagoriの設定と、実際の記事を変えないために、次の準備をしてから各項目へ進む。

### 検証用のWorkspaceを作る

実際の記事は開かず、複製だけを使う。

```sh
mkdir -p ~/NagoriQA
cp -R /path/to/your/blog-articles ~/NagoriQA/workspace
```

複製元は手元の記事フォルダに置き換える。`.git`と`node_modules`は複製しなくてよい。日本語、表、画像、リスト、数式を含む記事が1本以上あるフォルダを選ぶ。複製後、元のフォルダを開かない。

### 通常の設定と分けたQAアプリを使う

通常のNagoriは設定を`app.nagori.editor`の設定ディレクトリへ保存する。QAでは別の識別子で作ったアプリを使い、前回のWorkspaceやテーマを通常の設定と分ける。

```sh
npm ci
npm run tauri build -- --bundles app --ci --config '{"identifier":"app.nagori.editor.qa20261002","productName":"Nagori QA"}'
open "src-tauri/target/release/bundle/macos/Nagori QA.app"
```

識別子は日付などで変えてよい。設定は`~/Library/Application Support/<識別子>/settings.json`に保存される。実行前に、通常のNagoriの設定を触らなかったことを後で確かめるため、次のハッシュを控える。

```sh
shasum -a 256 ~/Library/Application\ Support/app.nagori.editor/settings.json
```

QA終了後に同じコマンドを実行し、値が一致することを共通の備考へ書く。通常のNagoriが起動中であれば、QAの前に終了しておく。

CLI登録の項目だけは、仕様どおりNagori.appを`/Applications`または`~/Applications`へ置く必要がある。その項目の準備を読むこと。

## 項目1 起動、作成、検索、再起動後の復帰

関連する仕様 §4.1、§4.2、§5、§16の1・2。

準備 共通準備のQAアプリを起動する。初回は前回のWorkspaceがないため、フォルダ選択画面が出る。

手順

1. フォルダ選択でキャンセルし、同じ画面にとどまることを見る。
2. `~/NagoriQA/workspace`を選ぶ。
3. 記事を1本開き、何も入力せずにCmd＋Sを押す。
4. 別のターミナルで、その記事のSHA-256を開く前の控えと比べる。
5. 記事を新規作成し、日本語の本文を入力する。500ms待つと「保存済み」になることを見る。
6. Cmd＋Pでファイル名の一部を入力し、候補から記事を開く。
7. Live PreviewとPreviewをCmd＋Shift＋Lで往復し、元の選択とスクロール位置が保たれることを見る。
8. Cmd＋Qで終了し、QAアプリを再度開く。

手順3の前に、対象記事のSHA-256を控える。

```sh
shasum -a 256 ~/NagoriQA/workspace/<記事>.md
```

期待結果 手順1でフォルダ選択が残る。手順4でSHA-256が控えと一致する。手順5で新規ファイルが保存される。手順6で候補から開ける。手順7で本文と保存状態が変わらない。手順8で前回のWorkspaceと最後に開いた記事が復帰する。

- 結果 不合格
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。
- 備考 手順1から6と8は期待どおりだった。手順1はフォルダ選択のキャンセルで同じ画面に戻った。手順3から4は記事Aを開いてCmd＋Sを押し、SHA-256が開く前と一致した。手順5は新規作成した記事に日本語を入力して500ms後に「保存済み」になり、ディスクにも同じ本文が入っていた。手順6はCmd＋Pに「記事B」を入れて候補から開けた。手順8はCmd＋Q後の再起動で、前回のWorkspaceと記事Bが復帰した。手順7ではカーソルは保たれたが、末尾までスクロールした状態でCmd＋Shift＋Lを2回往復すると、表示位置が約1行半ずれた。キャレットを画面内に入れる動作の可能性があり、先頭付近でのずれは見ていない。手順7のみ期待結果と違うため、軽微な不合格とし、再現条件の切り分けは残る。

## 項目2 終了経路と保存の一連操作

関連する仕様 §11.1、§11.2、§16の1・7・13。

準備 項目1と同じQAアプリとWorkspace。終了経路ごとに、毎回新しい行を末尾へ足す。足した行の文字列を控えておく。

手順 次の5つの経路で、それぞれ操作する。

1. Cmd＋Q
2. Cmd＋W
3. ウィンドウの閉じるボタン
4. アプリメニューの終了
5. Dockのアプリアイコンを右クリックして終了

各経路で次を行う。

1. 記事の末尾へ、日本語の一文を入力する。
2. 入力から1秒以内に終了操作をする。500msの自動保存が終わる前を狙う。
3. 終了するまでにダイアログや待機が出た場合は、その内容を備考へ書く。
4. QAアプリを再度開く。
5. 入力した一文が記事に残り、前回のWorkspaceと記事が開くことを見る。
6. ターミナルでファイルの末尾を表示し、ディスクにも同じ文字列が入っていることを確かめる。

```sh
tail -n 3 ~/NagoriQA/workspace/<記事>.md
```

加えて、Cmd＋Wの経路では、アプリがウィンドウを閉じても保存が完了してから終了することを見る。

期待結果 全経路で、最新の本文が再起動後に開いた記事とディスクの両方にある。前回のWorkspaceと記事が復帰する。保存に失敗する状況では終了が止まる。この停止は項目7で確認する。

| 経路 | 結果 | 備考 |
|---|---|---|
| Cmd＋Q | 合格 | 1秒以内の入力が再起動後とディスクに残った |
| Cmd＋W | 合格 | 同上。ウィンドウを閉じるとアプリも終了した |
| 閉じるボタン | 合格 | 同上 |
| アプリメニューの終了 | 未実施 | メニューバーがアクセシビリティツリーに出ず操作できなかった |
| Dockからの終了 | 未実施 | Dockは別のアプリのため操作せず。終了のApple Eventで代替すると直前の入力が失われた |

- 総合結果 未実施（3経路は合格）
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。
- 備考 Cmd＋Q、Cmd＋W、閉じるボタンの3経路は、入力から1秒以内に終了しても再起動後に最新の一文が残り、ディスクにも入っていた。終了までダイアログや待機は出なかった。再起動後は前回のWorkspaceと記事が復帰した。アプリメニューの終了は、メニューバーがアクセシビリティツリーに出ず操作できなかったため未実施。Dockからの終了は、Dockが別のアプリに当たるため操作せず未実施。Dockの終了は、アプリへ終了のApple Eventを送る点が共通のため、同じイベントをosascriptで送って代わりに確かめた。入力直後に送ると、直前に入力した語が保存されないまま終了した。2回続けて再現した。同じタイミングのCmd＋Qでは保存された。実際のDock操作では確かめていないので、Dock経路の結果は未実施のまま、不具合候補として残す。なお日本語変換中にCmd＋Qを送ると、アプリは終了しなかった。

## 項目3 日本語IME

関連する仕様 §7.3、§16の4。

準備 日本語IMEを有効にする。複製した記事を開き、本文の途中にカーソルを置く。Floating Toolbarが出る程度に選択できる文を用意する。

手順

1. 空の行に、ひらがなを入力して変換候補を表示する。変換を確定せずに候補を上下で選ぶ。この間、Floating Toolbarが出ないことを見る。
2. 変換中に既存のプレビューの装飾が維持されることを見る。太字、見出し、リンクを含む行の近くで入力する。
3. Enterで確定し、確定後に最新の本文と選択からプレビューが更新されることを見る。
4. 別の語を変換し、Escapeで変換をキャンセルする。入力途中の文字が本文に残らず、カーソル位置が変わらないことを見る。
5. 確定済みの日本語を選び、再変換する。再変換後に本文が壊れないことを見る。
6. 変換中の状態で、500ms以上待つ。自動保存が始まらず、確定後に保存が始まることを見る。
7. 変換中に記事の切り替えを試みる。確定またはキャンセルされるまで切り替わらず、途中の文字列が失われないことを見る。変換を確定すると切り替わる。
8. 変換中にCmd＋Shift＋Pを押し、コマンドパレットが開かないことを見る。
9. 確定後にCmd＋Zを押し、直前の入力だけが戻ることを見る。続けてShift＋Cmd＋Zで元へ戻る。
10. 自動保存が終わった後にもCmd＋Zで戻せることを見る。

期待結果 変換範囲が置換・非表示にならない。変換中にToolbarとパレットが出ない。確定後とキャンセル後に本文とカーソルが壊れない。自動保存後もUndoできる。

- 結果 未実施（一部確認）
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。日本語IMEはmacOS標準のひらがな入力で、候補ウィンドウが出た。IMEの正確な名称は画面から確認できなかった。
- 備考 手順1の候補表示、手順4のEscapeによるキャンセル、手順6の変換中の自動保存停止だけ確認した。aを入力して「あ」を変換中にすると、候補ウィンドウが出て、Floating Toolbarは出なかった。2秒以上待っても状態は「未保存」のままでファイルは変わらなかった。Escapeを2回押すと変換中の文字が本文から消え、保存済みになった。手順2、3、5、7から10は未実施。ASCIIの記号がひらがな入力のまま半角で打てず、再変換やコマンドパレットの確認まで進まなかった。

## 項目4 実記事での編集、選択、表、画像

関連する仕様 §6.2、§7.1、§7.2、§16の2・3・5。

準備 表、画像、リスト、引用、太字と斜体の入れ子、Front Matter、Raw HTML、完結していない記法を含む複製記事を開く。記事の最初のSHA-256を控える。

手順

1. 何も編集せずに記事を閲覧し、スクロールして、Live PreviewとPreviewを切り替える。SHA-256が変わらないことを見る。
2. 太字と斜体の入れ子にカーソルを置く。要素全体の記号と、入れ子にした親の記号が表示され、装飾が維持されることを見る。
3. 複数行を選択する。選択に交差するすべての要素の記号が表示されることを見る。
4. 引用の中のリストで行をまたいでカーソルを動かす。カーソルがある行の記号だけが表示され、親の構造が残ることを見る。
5. `**` だけ、`[` だけなど、完結していない記法を入力する。本文が壊れず、入力を続けられることを見る。
6. 表をクリックし、表全体がMarkdownソースへ切り替わることを見る。表の外へカーソルを動かすと、表示へ戻る。
7. 画像をクリックし、画像の記法へカーソルが移ることを見る。外へ出ると画像表示へ戻る。
8. Front Matterとコードブロック、Raw HTMLを開き、原文が保持されたまま編集できることを見る。
9. 長い記事で、選択とスクロールを行い、カーソルが画面内に残ることを見る。

期待結果 仕様§7.2の単位で記号が切り替わる。表示の切り替えでカーソル位置と選択範囲が変わらない。未対応記法とFront Matterの原文が保たれる。無編集のSHA-256が一致する。

- 結果 未実施（一部確認）
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。
- 備考 手順1、2、3、4、6、7、9を確認した。手順1は記事Cを開いて閲覧し、Live PreviewとPreviewを切り替えたあとSHA-256が控えと一致した。手順2はカーソルを太字と斜体の入れ子に置くと、外側と内側の記号が表示された。手順3は段落から引用リストの途中まで複数行を選択すると、太字、リンク、引用、リストの記号が表示された。手順4は引用内のリストで行を移動すると、カーソルの行だけに記号が出て、ほかの行は箇条書きのまま残った。手順6は表の編集ボタンで表がMarkdownソースになり、カーソルを上に動かすと表示へ戻った。手順7は画像の編集ボタンで記法に切り替わり、離れると戻った。手順9はCmd＋Downで末尾へ移動しても、キャレットは画面内にあった。手順5と8は未実施。入力できる記号に制限があり、未完の記法の入力や編集を確かめていない。画像が描画されることは、Previewでimage要素が出たことまでで、Live Previewでは見ていない。

補足として、操作ツールのtype-textでエディタへ入力した直後に、記事Cの本文が崩れたことがある。段落が並べ替わり、数式の描画文字が本文に混ざっていた。入力した文字も二重になっていた。アプリの不具合かツールの入力方式によるものかは切り分けられていない。再現手順は、記事Cを開いて表と画像のボタンを操作し、段落を複数行選択したあと、Cmd＋Downで末尾へ移動して、type-textで記号と英字を入力する。崩れた記事は複製であり、記事Aから戻した。

## 項目5 Previewの選択とコピー

関連する仕様 §7.3、§16の4。

準備 項目4の記事を使う。Cmd＋Shift＋LでPreviewへ切り替える。コピーした内容を確かめるために、テキストエディタなどの別アプリを用意する。

手順

1. Previewで本文を選択し、Markdownの記号が表示されないことを見る。
2. 選択した範囲をCmd＋Cでコピーし、別アプリへ貼り付けて内容を確かめる。
3. 表、数式、画像の近くをクリック・選択しても、編集表示へ戻らないことを見る。
4. Previewのまま、文字入力、貼り付け、切り取り、Cmd＋Z、Shift＋Cmd＋Z、Cmd＋B、画像挿入を試す。本文が変わらないことを見る。
5. タスクのチェックボックスをクリックし、チェックが変わらないことを見る。
6. Cmd＋Fで検索でき、スクロールできることを見る。
7. Live Previewへ戻り、本文、保存状態、Undo履歴が変わっていないことを見る。戻った後にCmd＋Zで直前の編集を戻せる。

期待結果 コピーできる。本文を変更する操作は無効になる。モードの切り替えで本文とUndo履歴が変わらない。

- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。

## 項目14 性能測定

関連する仕様 §14、§16の14。

準備 性能の判定はReleaseビルドで行う。共通準備のQAアプリを使い、通常の設定とは別の識別子であることを確かめる。測定条件は仕様§14.1に従う。

- 編集対象の記事は100KiBの日本語を含み、見出し・リスト・表・画像を含む

記事は固定して、すべての測定で同じ本文を使う。測定前に本文のSHA-256を控え、測定後に一致を確かめる。他のアプリを閉じ、ライトテーマ、本文19px、同じウィンドウサイズで測る。測定値は毎回、環境と一緒に記録する。環境が異なる値は混ぜて比べない。

手順

1. 記事を開いた状態で、アプリを終了し、起動から本文を入力できるまでの時間を、Cold起動とWarm起動で複数回測る。目標は2秒以内。
2. 通常の入力から画面反映までの遅延を測る。目標は95パーセンタイルで50ms以内。測定ツールがない場合は、目視で入力停止がないことだけを記録し、数値は未測定と書く。
3. Quick Openで文字を入力し、検索の更新を測る。目標は95パーセンタイルで100ms以内。
4. 起動後30秒経過した状態で、アプリと専用WebView関連プロセスの合計メモリを測る。目標は100MiB以下。努力目標であり、配布条件ではない。

メモリは、アプリのPIDと、その責任下にあるプロセスを対象にする。

```sh
pgrep -f "Nagori QA"
footprint -f bytes -w -p <アプリのPID> -p <WebContentのPID> -p <GPUのPID> -p <NetworkingのPID>
```

5. 日本語IME、表の表示切り替え、画像を含む文書で、目視できる入力停止がないことを見る。
6. 10枚程度の画像を含む記事を全体までスクロールし、停止がないことを見る。
7. 数式の記事を開き、通常の記事へ戻して、メモリが戻るかを時間を置いて記録する。
8. 編集上限付近のMarkdown、大量のファイル、上限付近の画像でも、操作不能にならないことを見る。

期待結果 測定値を条件と一緒に記録する。目標を満たさない項目は、その値と判断を記録する。入力停止など日常の編集を妨げる問題が残らない。

## 実施後の整理

1. 権限を変更したファイルとフォルダを元へ戻す。
2. `~/NagoriQA`と、`~/Applications`へコピーしたQAアプリを削除する。
3. 通常のNagoriの設定SHAを、共通準備の控えと比べる。
4. `command -v nagori`で、`/usr/local/bin/nagori`が開始前の状態へ戻ったことを確かめる。
5. 結果を転記する場合は、不合格と未実施の項目を残したまま、[検証状況](verification.md)と[実装計画](implementation-plan.md)へ事実だけを書く。
