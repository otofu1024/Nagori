## 共通準備

通常のNagoriの設定と、実際の記事を変えないために、次の準備をしてから各項目へ進む。

### 検証用のWorkspaceを作る

実際の記事は開かず、複製だけを使う。

```sh
mkdir -p ~/NagoriQA
cp -R /path/to/your/blog-articles ~/NagoriQA/workspace
```

複製元は手元の記事フォルダに置き換える。`.git`と`node_modules`は複製しなくてよい。日本語、表、画像、リスト、数式を含む記事が1本以上あるフォルダを選ぶ。複製後、元のフォルダを開かない。

### 通常の設定と分けたQAアプリを使う

通常のNagoriは設定を`app.nagori.editor`の設定ディレクトリへ保存する。QAでは別の識別子で作ったアプリを使い、前回のWorkspaceやテーマを通常の設定と分ける。

```sh
npm ci
npm run tauri build -- --bundles app --ci --config '{"identifier":"app.nagori.editor.qa20261002","productName":"Nagori QA"}'
open "src-tauri/target/release/bundle/macos/Nagori QA.app"
```

識別子は日付などで変えてよい。設定は`~/Library/Application Support/<識別子>/settings.json`に保存される。実行前に、通常のNagoriの設定を触らなかったことを後で確かめるため、次のハッシュを控える。

```sh
shasum -a 256 ~/Library/Application\ Support/app.nagori.editor/settings.json
```

QA終了後に同じコマンドを実行し、値が一致することを共通の備考へ書く。通常のNagoriが起動中であれば、QAの前に終了しておく。

CLI登録の項目だけは、仕様どおりNagori.appを`/Applications`または`~/Applications`へ置く必要がある。その項目の準備を読むこと。

## 項目1 起動、作成、検索、再起動後の復帰

関連する仕様 §4.1、§4.2、§5、§16の1・2。

準備 共通準備のQAアプリを起動する。初回は前回のWorkspaceがないため、フォルダ選択画面が出る。

手順

1. フォルダ選択でキャンセルし、同じ画面にとどまることを見る。
2. `~/NagoriQA/workspace`を選ぶ。
3. 記事を1本開き、何も入力せずにCmd＋Sを押す。
4. 別のターミナルで、その記事のSHA-256を開く前の控えと比べる。
5. 記事を新規作成し、日本語の本文を入力する。500ms待つと「保存済み」になることを見る。
6. Cmd＋Pでファイル名の一部を入力し、候補から記事を開く。
7. Live PreviewとPreviewをCmd＋Shift＋Lで往復し、元の選択とスクロール位置が保たれることを見る。
8. Cmd＋Qで終了し、QAアプリを再度開く。

手順3の前に、対象記事のSHA-256を控える。

```sh
shasum -a 256 ~/NagoriQA/workspace/<記事>.md
```

期待結果 手順1でフォルダ選択が残る。手順4でSHA-256が控えと一致する。手順5で新規ファイルが保存される。手順6で候補から開ける。手順7で本文と保存状態が変わらない。手順8で前回のWorkspaceと最後に開いた記事が復帰する。

- 結果 不合格
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。
- 備考 手順1から6と8は期待どおりだった。手順1はフォルダ選択のキャンセルで同じ画面に戻った。手順3から4は記事Aを開いてCmd＋Sを押し、SHA-256が開く前と一致した。手順5は新規作成した記事に日本語を入力して500ms後に「保存済み」になり、ディスクにも同じ本文が入っていた。手順6はCmd＋Pに「記事B」を入れて候補から開けた。手順8はCmd＋Q後の再起動で、前回のWorkspaceと記事Bが復帰した。手順7ではカーソルは保たれたが、末尾までスクロールした状態でCmd＋Shift＋Lを2回往復すると、表示位置が約1行半ずれた。キャレットを画面内に入れる動作の可能性があり、先頭付近でのずれは見ていない。手順7のみ期待結果と違うため、軽微な不合格とし、再現条件の切り分けは残る。
- コード調査（2026-10-03） 表示切り替え時のスクロール復元がscrollTopのピクセル値を固定で戻していたことが、ずれの原因と考えられる。末尾にいるとき、切り替えで文書の高さが縮むとscrollTopが新しい末尾へ丸められ、戻して高さが伸びると、縮んだ分だけ末尾から離れる。src/lib/scrollRestore.tsを追加し、切り替え前に末尾にいた場合は切り替え後も末尾へ合わせるようにした。先頭付近など末尾でない場合は従来どおりscrollTopを保つ。判定関数はNodeで確認した。実際のWKWebViewで約1行半のずれが消えたことは、GUIで未確認。

## 項目1a ファイル内の検索と置換

関連する仕様§10.2。

英数字の入力: Cmd+Fで開き、`autumn`のような英単語を1文字ずつ打つ。入力欄の文字が消えずに積み上がり、件数が単語全体の一致で絞り込まれることを確かめる。Enterで次へ移った後も、続けて打った文字が入力欄の末尾に足されることを確かめる。

準備 複製したMarkdownと`.txt`に、`cat CAT cat12 cat34`、日本語の同じ語、複数行を用意する。ライトとダークの両方で確認する。

1. Cmd＋Fで検索し、初期状態が大文字小文字を区別する文字列検索になっていることを見る。件数、EnterとShift＋Enter、前へと次へ、文末からの折り返し、Escapeと閉じるを確認する。
2. 大文字小文字の区別を外して件数が増えることを見る。正規表現をオンにし、`(cat)(\d+)`で数字付きの語を検索する。切り替えの押された状態とフォーカスの枠を見る。
3. `[`を入力し、「正規表現が正しくありません」と検索欄のエラー表示が出ることを見る。本文が変わらず、正しい式へ戻すと検索が再開する。
4. `^`を検索し、前後への移動で次の行へ進むことを見る。「置換欄」を開いて`>`へ全置換し、処理が完了して各行の先頭に入ることを見る。
5. `(cat)(\d+)`を`$2-$1-$&-$$`へ置換する。置換欄のEnterは選択中の1件を変更して次へ進む。Cmd＋Enterと「すべて置換」は全件を変更し、「N件を置換しました」と出る。文字列検索では`$1`などを文字として挿入する。
6. 置換前に本文を1文字入力してから全置換する。本文へフォーカスを戻し、1回のCmd＋Zで全置換だけが戻ることを見る。さらに戻すと直前の入力が戻り、Redoで両方を復元できる。
7. TabとShift＋Tabで入力欄とボタンを順に移る。検索欄と置換欄で日本語を変換し、Enterで確定した時に検索移動や置換が実行されないことを見る。確定後に検索条件と置換文字列が反映される。
8. 読み取り専用、ファイル処理中、保存中、Previewで置換ボタンが無効になり、検索は使えることを見る。状態を解除すると置換が戻る。`.txt`でも検索と置換ができる。
9. 2段のパネルで本文が見えることを確かめる。幅を狭めても入力欄とボタンを操作できる。保存と再読み込み、IME、Undo、Live Preview、目次、右クリックメニュー、画像の貼り付けが従来どおり動くことを見る。

期待結果 検索と置換が両方のファイル種別で動き、無効条件を守る。全置換は1回でUndoできる。

## 項目2 終了経路と保存の一連操作

関連する仕様 §11.1、§11.2、§16の1・7・13。

準備 項目1と同じQAアプリとWorkspace。終了経路ごとに、毎回新しい行を末尾へ足す。足した行の文字列を控えておく。

手順 次の5つの経路で、それぞれ操作する。

1. Cmd＋Q
2. Cmd＋W
3. ウィンドウの閉じるボタン
4. アプリメニューの終了
5. Dockのアプリアイコンを右クリックして終了

各経路で次を行う。

1. 記事の末尾へ、日本語の一文を入力する。
2. 入力から1秒以内に終了操作をする。500msの自動保存が終わる前を狙う。
3. 終了するまでにダイアログや待機が出た場合は、その内容を備考へ書く。
4. QAアプリを再度開く。
5. 入力した一文が記事に残り、前回のWorkspaceと記事が開くことを見る。
6. ターミナルでファイルの末尾を表示し、ディスクにも同じ文字列が入っていることを確かめる。

```sh
tail -n 3 ~/NagoriQA/workspace/<記事>.md
```

加えて、Cmd＋Wの経路では、アプリがウィンドウを閉じても保存が完了してから終了することを見る。

期待結果 全経路で、最新の本文が再起動後に開いた記事とディスクの両方にある。前回のWorkspaceと記事が復帰する。保存に失敗する状況では終了が止まる。この停止は項目7で確認する。

| 経路 | 結果 | 備考 |
|---|---|---|
| Cmd＋Q | 合格 | 1秒以内の入力が再起動後とディスクに残った |
| Cmd＋W | 合格 | 同上。ウィンドウを閉じるとアプリも終了した |
| 閉じるボタン | 合格 | 同上 |
| アプリメニューの終了 | 未実施 | メニューバーがアクセシビリティツリーに出ず操作できなかった |
| Dockからの終了 | 未実施 | Dockは別のアプリのため操作せず。終了のApple Eventで代替すると直前の入力が失われたが、修正後は保存された（備考を参照） |

- 総合結果 未実施（3経路は合格）
- 実施日と環境 2026-10-03、macOS 26.6.2、Mac16,12、Nagori QA（識別子app.nagori.editor.qa20261003のReleaseビルド、ダークテーマ、本文19px、1120×800）。操作はOrcaのcomputer-useで行い、画面と操作後のアクセシビリティツリーで確認した。
- 備考 Cmd＋Q、Cmd＋W、閉じるボタンの3経路は、入力から1秒以内に終了しても再起動後に最新の一文が残り、ディスクにも入っていた。終了までダイアログや待機は出なかった。再起動後は前回のWorkspaceと記事が復帰した。アプリメニューの終了は、メニューバーがアクセシビリティツリーに出ず操作できなかったため未実施。Dockからの終了は、Dockが別のアプリに当たるため操作せず未実施。Dockの終了は、アプリへ終了のApple Eventを送る点が共通のため、同じイベントをosascriptで送って代わりに確かめた。入力直後に送ると、直前に入力した語が保存されないまま終了した。2回続けて再現した。同じタイミングのCmd＋Qでは保存された。実際のDock操作では確かめていないので、Dock経路の結果は未実施のままとする。原因は、tao 0.37.1がApple Eventの終了をapplicationWillTerminateへ直行させ、RunEvent::ExitRequestedとフロントの保存を通らないことだと読み取った。ExitRequestedの発火有無そのものはログで確かめていない。src-tauri/src/lib.rsのapple_quitで、アプリのデリゲートへapplicationShouldTerminate:を足し、保存が済むまで終了を取り消してnagori:quit-requestedを送る形にした。修正後のQAアプリ（識別子app.nagori.editor.qa20261003、製品名Nagori QA Quit）で、入力直後にosascriptで終了を送る手順を3回行い、3回とも入力が記事に残り、アプリは終了した。osascript側には、終了を一度取り消すため「ユーザによってキャンセルされました (-128)」のエラーが返るが、アプリはその後終了した。Dockからの実操作は引き続き未確認。なお日本語変換中にCmd＋Qを送ると、アプリは終了しなかった。

## 項目3a 段落途中の変換とカーソルの高さ

準備 本文19pxで2行以上に折り返す段落を用意する。普通の段落、太字とリンクの内側、見出し、読点と閉じかぎ括弧の前後で試す。全角スペースで字下げし、途中に太字がある段落も用意する。太字の内側では、入力する語と同じ語が直後に続く位置でも試す。

1. 2行目以降の途中へカーソルを置く。ひらがなを入力し、スペースで候補を繰り返し切り替える。文節を左右へ移し、文頭など別の位置へ移らないことを見る。
2. 入力中と変換中の線が、変換していない時と同じ文字の高さに収まることを見る。上の行まで伸びず、入力と文節移動の直後に点灯し、その後は点滅することを確かめる。
3. 未確定文字の下線と文節の選択を確かめる。候補ウィンドウが入力している文字の近くに出ることを見る。

準備 複製した記事を開く。元の画像として、PNG、JPEG、GIF、WebPのいずれかを`~/NagoriQA/images`へ置く。空白や括弧を含む名前の画像も1枚用意する。記事と同じフォルダの`assets`に同名の画像がある状態も作る。

手順

1. 記事の途中にカーソルを置き、本文の右クリックメニューから「画像を挿入」を選ぶ。
2. ファイル選択ダイアログで、通常名の画像を選ぶ。
3. 記事の隣の`assets`に画像がコピーされ、元の画像が残ることを、Finderまたはターミナルで確かめる。
4. カーソル位置へ相対パスの画像記法が入り、Live Previewで画像が表示されることを見る。
5. 同名の画像を再度挿入し、既存のファイルが上書きされず、番号が付くことを見る。
6. 空白や括弧を含む名前の画像を挿入し、記法が正しく解釈されて表示されることを見る。
7. Cmd＋Zを押す。挿入した記法だけが本文から戻り、コピーした画像が`assets`に残ることを見る。
8. Previewへ切り替え、「画像を挿入」が使えないことを見る。
9. Live Previewへ戻り、スクリーンショットをクリップボードへ撮る(Cmd＋Ctrl＋Shift＋4)。記事の途中でCmd＋Vを押し、`assets`に`pasted-image.png`が作られて記法が挿入され、画像が表示されることを見る。もう一度貼り付けると`pasted-image-1.png`になることも見る。
10. 文字と画像を一緒にコピーした状態(ブラウザで画像を含む範囲をコピーするなど)で貼り付け、文字として貼り付けられ、`assets`に画像が増えないことを見る。
9. 画像の選択ダイアログをキャンセルし、本文が変わらないことを見る。

```sh
ls -la ~/NagoriQA/workspace/<記事のフォルダ>/assets
shasum -a 256 ~/NagoriQA/images/<画像>
shasum -a 256 ~/NagoriQA/workspace/<記事のフォルダ>/assets/<画像>
```

期待結果 元ファイルと同名の既存画像を上書きしない。生成した相対パスで画像が表示される。Undoは本文だけを戻し、コピー済みの画像を削除しない。

## 項目14 性能測定

関連する仕様 §14、§16の14。

準備 性能の判定はReleaseビルドで行う。共通準備のQAアプリを使い、通常の設定とは別の識別子であることを確かめる。測定条件は仕様§14.1に従う。

- 対象ファイル数1,000
- 編集対象の記事は100KiBの日本語を含み、見出し・リスト・表・画像を含む
- 起動時にネットワークを使わない

記事は固定して、すべての測定で同じ本文を使う。測定前に本文のSHA-256を控え、測定後に一致を確かめる。他のアプリを閉じ、ライトテーマ、本文19px、同じウィンドウサイズで測る。測定値は毎回、環境と一緒に記録する。環境が異なる値は混ぜて比べない。

手順

1. 記事を開いた状態で、アプリを終了し、起動から本文を入力できるまでの時間を、Cold起動とWarm起動で複数回測る。目標は2秒以内。
2. 通常の入力から画面反映までの遅延を測る。目標は95パーセンタイルで50ms以内。測定ツールがない場合は、目視で入力停止がないことだけを記録し、数値は未測定と書く。
3. Quick Openで文字を入力し、検索の更新を測る。目標は95パーセンタイルで100ms以内。
4. 起動後30秒経過した状態で、アプリと専用WebView関連プロセスの合計メモリを測る。目標は100MiB以下。努力目標であり、配布条件ではない。

メモリは、アプリのPIDと、その責任下にあるプロセスを対象にする。

```sh
pgrep -f "Nagori QA"
footprint -f bytes -w -p <アプリのPID> -p <WebContentのPID> -p <GPUのPID> -p <NetworkingのPID>
```

6. 10枚程度の画像を含む記事を全体までスクロールし、停止がないことを見る。
7. 数式の記事を開き、通常の記事へ戻して、メモリが戻るかを時間を置いて記録する。
8. 編集上限付近のMarkdown、大量のファイル、上限付近の画像でも、操作不能にならないことを見る。
